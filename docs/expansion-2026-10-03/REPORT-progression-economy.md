# Общая прогрессия, узкая миграция рыбалки и резервы ставок

Локальная подзадача завершена. **57/57 целевых проверок прошли**. Production, рабочие сохранения, SSH, сервер и браузер в этой подзадаче не запускались. Общая интеграция сообщений/сцен/эффектов/источников наград и финальный gate принадлежат головному агенту.

## Сохранение и миграция

`Profile` получает независимые `xp`, `level`, `levelsVersion=1`, `fishingResetVersion=1`. При первой нормализации старого профиля общий XP один раз оценивается по сохранённым счётчикам: гонка×20, раунд пейнтбола×15, дурак×20, улов×3, аквапарк×5, крепость×20, бой×15. Для уловов берётся максимум `fsCaught/fsFish`, а не их сумма; исторический коэффициент приблизительный и не использует казино/баланс/рыбацкий XP. Новые профили сразу имеют текущие версии и XP=0.

**Разрешённый сброс:** только `fishing.xp`, `questsDone`, `questCaught`, `rod` становятся нулями. Удочки снова зарабатываются. `beerUntil`, альбом, количества/виды/веса/максимумы/забросы/поклёвки/срывы/заработок, жетоны, вещи, остальные рекорды и статистика не сбрасываются. Повторная нормализация с маркером сохраняет новый прогресс.

Замороженный **синтетический профиль старого формата**, а не реальный профиль игрока: `test/fixtures/profile-before-progression.json`. Тест сравнивает все его прежние Stats и поля вне разрешённой миграции. Проверка реальной временной JSON-записи дополнительно доказывает, что последующий рыбацкий прогресс и маркеры переживают два перезапуска; незавершённый Blackjack escrow возвращается единожды.

Для выпуска всё ещё требуется разрешённый снимок после остановки сервера и read-only сравнение нормализации с актуальным сохранением по AGENTS.md. Старый код не считать безопасным откатом: он не знает новые поля. Реальное обнуление здесь не выполнялось.

## Общие уровни

`shared/levels.ts`: `xpToNext(level)=100+40×level`; начало уровней 5/15/30/50 — 800/5600/20300/53900 XP. При ориентире 10 жетонов/мин это 1,3/9,3/33,8/89,8 часов активной игры: вечер / несколько вечеров-неделя / месяц / долгосрочная цель. Это модель по указанному темпу, не измерение фактических наград всех режимов.

Рамки: none, bronze, silver, gold, diamond. API: `levelFromXp`, `xpForLevel`, `xpToNext`, `levelProgress`, `frameForLevel`, `FRAME_TIERS`.

`Profiles.credit(profile, amount, 'mode')` даёт XP 1:1 с целой положительной наградой; источник по умолчанию `'other'` не даёт XP. NaN/Infinity/отрицательные начисления отвергаются. Квестовая награда уже отмечена `'mode'` в Profiles. Остальные вызовы в режимах маркирует исполнитель общей серверной интеграции; автоматы остаются default, Blackjack settlement опыта не даёт.

`Profiles.onLevel(profile,event)` получает ровно одно событие на начисление, даже при пересечении нескольких уровней. `LevelUp={from,level,xp,tier,milestones}`; `milestones` — только пересечённые границы рамок. Начальный исторический пересчёт тихий. Главный агент использует событие для плашки/искр/звука и чата только при `milestones.length>0`.

## Деньги карточных игр

Blackjack reserve/settle и возврат при старте сохранены. Добавлен независимый `durakEscrow`.

- `reserveDurakBatch(round,bets:[{pid,amount}])`: валидация всех 1–6 участников до списания, уникальные PID, достаточный баланс, отсутствие другой незавершённой партии; все списания и escrow записываются одной атомарной записью.
- `settleDurak(round,payouts:[{pid,wager,payout}])`: полный набор резервов партии, точная ставка каждого, сумма выплат строго равна банку; частичный/повторный/несогласованный расчёт отвергается до изменений.
- Общий XP только за положительную разницу `payout-wager`; возврат ставки и бесплатная игра XP из этого API не дают. UI/зал определяет победителя/возврат по согласованным правилам.
- Балансы, удаление резервов и XP сохраняются до callback уровня. Тест читает JSON прямо из callback и проверяет, что весь расчёт уже сохранён.
- После аварийного старта оба незавершённых escrow возвращаются один раз без XP. Двойной reload не дублирует возврат.

## Рыбалка и новые счётчики

Текущий квест растёт только до `questNeed`; пока награда не забрана, последующие уловы не копятся в следующий квест. Выдача обнуляет счётчик, включая исторический избыток. Проверено семь успешных рыб при первом требовании 5: счётчик остаётся 5 до получения.

Обычный и вызванный бубном дождь используют один диапазон **288–480 секунд** (4:48–8:00, верхняя граница генератора исключена). Активное событие не продлевается. Стоимость бубна этим исполнителем не менялась.

Подиум хранит **пять отдельных уловов дня по Москве**, включая несколько уловов одного игрока. Ограничение обновлено при накоплении, выдаче и загрузке. Четыре прежних рейтинга по количеству/весу не менялись.

Добавлены нулевые Stats для координируемых новых режимов: `stStorms/stLights`, `prRaids/prWins/prKos`, `brRaces/brWins/brBestLap` (последнее в тиках), `hiGames/hiWins/hiFound/hiSurvived`. `rcBestLapFoundry` и цены гардероба сохранены. `State.lobbyEvents` сохраняет `stormAt/piratesAt/endedAt/lockUntil` как конечные неотрицательные timestamps; логика событий находится у другого исполнителя.

## Клиент и ресурсы

`Avatar.setLevel(level)` или четвёртый аргумент `setInfo(name,team,mate,level)` обновляет ту же CanvasTexture и Sprite ника. Новых 3D-объектов на кадр нет. Уровень в кружке, ступенчатая рамка, серебро+ получает короткий перелив до 8 перерисовок раз в 8 секунд только при видимой табличке. `prefers-reduced-motion` отключает перелив. В командных режимах цвет команды важнее — престижная рамка подавлена. Код деформации шапок/гардероба не менялся.

ProfilePanel показывает общий уровень, доступный `<progress>`, текущий/необходимый XP и четыре Canvas-примера рамок; будущие рамки серые. Навык рыбалки остаётся отдельным. Добавлены условные блоки новых режимов после первой игры. Profiles.honor теперь также возвращает level рядом с nick; отображение на общей доске/списках подключает головной агент.

Изменённые production-файлы: `shared/levels.ts` (новый), `shared/economy.ts`, `server/store.ts`, `server/profiles.ts`, `server/lobby/fishing2.ts` (только cap/импорт), `server/lobby/fishtop.ts`, `server/lobby/weather.ts`, `client/ui/profile.ts`, `client/ui/levelprogress.ts`/`levels.css` (новые), `client/render/avatar.ts` (только табличка/уровень), `client/render/leveltag.ts` (новый).
