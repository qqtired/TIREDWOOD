## Меняем

| Где | Что |
|---|---|
| Везде | бейдж (портрет, уровень, жетоны, «+N»), чат и голос, эмоции, подсказка «E», плашка события и тосты верх-центра, крупный баннер (`.k-hero`), счётчик FPS, ники и реплики над головами, пузыри чата |
| Рыбалка | карточка уровня и «Шансы сейчас», плитки задания, рюкзака, напитка, лодки; подсказки внизу; рамка шкалы вываживания (размытая подложка остаётся); карточка улова |
| Ферма | карточка уровня и задания, плашка Древа, плитки сумки, вёдер, лейки, пояс семян |
| Крепость | низ: здоровье, оружие, граната, патроны, рывок; карточка «Новичку»; **предложение** верха и мини-карты (если не понравится — текущий) |
| Режимы | картинг (место, круг, мини-карта, бонус, скорость), пейнтбол (табло, лента сбитых, панель бойца), «Выше облаков», прятки, регата, «Стриж», пираты и шторм, HUD крысиных бегов и «Ракушки» |

Технически почти всё это — один набор деталей кита (`client/ui/kit/`): HUD берёт только переменные `--h-*`,
`--plate-*`, `--chat-*`, `--mh-*`, вариант задаётся атрибутом `data-hud` на `<html>` (сейчас `light`). Значит, новое
направление = новый блок токенов `[data-hud='…']` в `tokens.css` + немного своих правил для деталей. Исключения,
где цвета зашиты в код: ники над головами (`render/leveltag.ts`), мини-карты картинга и крепости (canvas),
верх крепости (`fort/ui/ui.css`, свои `--dg-*`).

## Цель — что должно стать лучше (четыре жалобы владельца)

1. **«Блёкло, как сайт».** HUD должен выглядеть частью игры про солнечный приморский городок: материал, характер,
   «вещь», а не белая карточка из приложения.
2. **«Разнобой».** Новый HUD — родня любимых экранов (блэкджек, бильярд, верх крепости, окна «Ретро-парка»), чтобы
   режимы не выглядели собранными из разных игр.
3. **«Плохо читается».** Текст и числа читаются на ярком небе, воде, песке и плитке без напряжения: контрастная
   подложка или обводка, крупные числа, без тонких серых подписей.
4. **«Много места».** Каждый вариант не больше нынешнего, лучше на 10–20 % компактнее: меньше слов, меньше
   двойных рамок, плотнее отступы. Вместе HUD не больше 1/8 экрана (`docs/ui.md` §3).

## Четыре направления

Каждое — родня того, что владельцу уже нравится. Раскладка и состав HUD у всех одинаковые, меняется только вид.

| Направление | Родня | Материал и цвет | Риск |
|---|---|---|---|
| **«Веранда»** | блэкджек, бильярд, дурак, верх крепости | тёмное тёплое «стекло» (без размытия) цвета сливы и шоколада, тонкая золотая кайма, кремовый текст, золотые числа | темновато для солнечного городка |
| **«Причал»** | верх крепости, пирс, лодки | лакированное дерево, латунная кайма и таблички, канат как разделитель; числа — кремом и золотом | тяжело и громоздко, если переборщить с фактурой |
| **«Светлый 2.0»** | нынешний HUD, курортные значки | фарфор и бумага, цветная эмалевая кромка режима, иконки в цветных медальонах, крупные жирные числа, тёмная «наклейная» обводка для контраста | может остаться «сайтом» |
| **«Вывеска»** | окна «Ретро-парк 2.0», вывески площади | плотная бирюзовая эмаль, кремовый кант 2 px, тёмная внешняя обводка, числа на кремовых вставках | 11.10 владелец сказал, что HUD в эмали хуже читается — это нужно исправить |

## Общие правила для всех вариантов

- Текст — Rubik; заголовочный Rubik Mono One — только для крупных баннеров, если идёт стилю. Других шрифтов нет.
- Без `backdrop-filter` (единственное исключение — подложка шкалы вываживания), без неона, без стекла с размытием.
- Иконки — нынешние картинки imagegen (`client/assets/ui/icons/`), эмодзи как иконки не добавлять.
- Размеры — `docs/ui.md` §3: текст ≥ 14 (13 — только третичное), бейдж 44, плитка 54, тост ≤ 360, плашка
  события ≤ 440, подсказка 42, чат 360, карточка режима 280–300. Всё в пикселях сцены 1440×900.
- Своё — золотом, опасность — красным; цвета редкости рыбы — только `--tier-*`.
- Фактуры — CSS-градиенты или маленькие бесшовные картинки imagegen (дерево, латунь, бумага, стекло) с `PROVENANCE`;
  плашки остаются дешёвыми для кадра. Референсы направлений и любые картинки — через imagegen в Codex CLI
  (напоминание владельца 30.10), без надписей на картинке.
- Каждый вариант задаётся блоком токенов `[data-hud='<id>']` + правилами деталей под тем же селектором.
  Id: `veranda`, `prichal`, `light2`, `vyveska`. Нынешний — `light`.

## Бильярд — UX ставки (вид не трогаем)

Проблема: новичок не понимает, как сыграть без ставки или поставить; если жетонов нет, все варианты всё равно видны.
Предложение для лаборатории:
- три понятных пути с первого взгляда: «Тренировка» (один, без ставки), «Партия без ставки», «Партия на жетоны»;
- ставка показывается только в пути «на жетоны»; фишки дороже баланса — неактивны с причиной («У тебя 40 🪙»);
- при 0 жетонов путь «на жетоны» неактивен с подсказкой «Сыграй без ставки — жетоны дают другие режимы»;
- кнопка всегда говорит, что произойдёт: «Позвать сыграть без ставки», «Позвать на 50 🪙».
Только раскладка и тексты панели `lobby/billiardshud.ts`; правила, экономика и сервер не меняются.

## Выкатка

Решения владельца 31.10 (через ведущего релиза): «Ждать новый HUD, выпустить всё вместе»; вывески — «Вместе с новым HUD»;
табло «Загадки» «Панели» — «Да, вместо старого»; выкладка — «Сначала отчёт, потом скажу «да»». Поэтому HUD v3 и вывески v3 —
за одним флагом сервера `UI3` (только явная `1`, даже в dev; `shared/ui3.ts`): сервер отдаёт `ui: 3` в `/health`, браузер
узнаёт его до загрузки игры (`client/layout-boot.ts`, как раскладку площади) и ставит `data-hud='veranda3'` на `<html>`. Без
флага — HUD «Светлый» и прежние вывески, ровно как раньше. Включить на сайте — строка `Environment=UI3=1` в
`deploy/game-opus.service` после «да» владельца; откат — убрать строку. «Панели» — по умолчанию, без флага (откат —
`RIDDLE2 = false` в `board-riddle.ts`). Окна (`data-skin='retro2'`), экран входа и экраны загрузки между режимами не меняются.
