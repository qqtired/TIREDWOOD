# Рекорды при смене трасс

Локальная совместимость четырёх обновляемых режимов. Старые результаты архивируются до выбора нового курса.
Счётчики за всё время, баланс, вещи, рыбалка, опыт и прочий прогресс не сбрасываются. Проверки используют только
искусственные данные в новых временных папках; боевое сохранение не читалось и не менялось.

## Контракт

| Режим | Текущий результат | Что сохраняется |
|---|---|---|
| Картинг, runtime `harbor` / `hills` | `rcBestLapHarborV3`, `rcBestLapHillsV3`, мс | `rcBestLapHarbor`, `rcBestLapHills`, более ранние `rcBestLap` / `rcBestLapFoundry`; общие заезды/победы/подиумы |
| Катера, `white-cliffs-v2` | `brBestLapCliffs`, тики; текущая `State.regatta` в мс | `brBestLapHarbor`, `brBestLap`; `State.regattaArchive[courseId]`; общие заезды/победы |
| Аквапарк | `State.aquaCourse`, текущая `State.aqua`; совместимое `Stats.aqBest` | `State.aquaArchive[courseId]`, `Profile.aquaBests[courseId]`; общий `aqRuns` |
| Каланча | `State.skillCourse`; совместимые `skBest`, `skMedal`, `skClean` | `Profile.skillRecords[courseId] = { best, medal, clean, day, runs }`; общий `skRuns` и оплаченный день `skDay` |

Аквапарк получает идентификатор из `AQUA_COURSE`: после интеграции `pick(2, () => 3)` означает курс 3 только
при `PLAZA3=1`. Каланча использует `sky-tower-v1` (65 м) по умолчанию; только `SKILL_TOWER2=1` выбирает
`cloud-tower-185-v2` (185 м). `Hub` передаёт тот же курс из Store в `SkillRoom` и `applySkillFinish`, поэтому
геометрия, медали и личный результат должны принадлежать одной версии.

Форма сообщений и `PROTOCOL_VERSION` не менялись. В существующем числовом `Stats` добавлены проекции
для карточек профиля: `aqCourse`, `aqBestCourse1/2/3`, `skCourse`, `sk*Legacy`, `sk*Tower185`. Канонические
полные архивы остаются в профиле. Карточки явно подписывают текущую трассу и прежние результаты; старые
65 м не сравниваются с новым подъёмом 185 м.

## Нормализация и повторная запись

1. Прочитать старый активный course id. Отсутствующий номер аквапарка — курс 1; отсутствующий курс каланчи —
   `sky-tower-v1`. Неизвестные корректные строковые идентификаторы уже имеющихся архивов сохраняются.
2. Объединить старую текущую доску с архивом её курса. Для одного участника остаётся лучшее время; список
   архивных участников не обрезается до пяти строк. Ограничение пяти применяется к действующей доске.
3. Сохранить личный активный результат перед его заменой. Два времени сравниваются только внутри одного
   курса; для медали, значка и числа подъёмов сохраняется накопленное значение.
4. Выбрать результат целевого курса. Если его ещё нет — новый текущий результат пустой. Если курс уже был
   архивирован — восстановить его лучший результат и таблицу.
5. Перед атомарной записью синхронизировать текущие записи и проекции. Свежая резервная копия при чтении
   уже не получает дополнительную миграцию. Повторное чтение/сохранение идемпотентно.

`skDay` остаётся общим ограничителем ежедневной выплаты: при выборе курса берётся максимальный уже
оплаченный день. Переключение версий не выдаёт daily-бонус повторно. При этом дата в архивной записи старой
каланчи не переписывается датой нового курса: её обновляет только настоящий финиш на старой каланче.

Неподходящие элементы архивов отбрасываются отдельно, не стирая соседние корректные записи. Числовые
времена проверяются на конечность/положительность; служебные ключи прототипа не принимаются. Значения,
которые уже были сохранены в числовых проекциях известных курсов, также восстанавливают личный архив.

`StoreOptions.recordCourses` позволяет проверить выбор и возврат курсов на отдельной копии без изменения
окружения процесса. Это используется в тестах. В штатном запуске Store выбирает текущие константы/флаг.

## Проверка

Node `v24.15.0`; **90/90** узких проверок прошли:

```sh
node --test --test-concurrency=1 \
  test/course-records-migration.test.ts test/store.test.ts test/store-recovery.test.ts \
  test/aqua.test.ts test/skilltest.test.ts test/hub.test.ts \
  test/expansion-hub.test.ts test/profiles.test.ts
```

Четыре искусственных набора покрывают старую схему, уже новую схему с архивами, повторную запись и возврат
3 → 2 → 3 / новая → старая → новая каланча, а также повреждённые элементы. Проверены сохранность жетонов,
вещей, опыта, рыбалки, накопленных счётчиков и прежних кругов; архив больше пяти участников; сохранённая
дата прежней каланчи; отсутствие повторной daily-выплаты. Отдельный Hub-тест проверяет запись `brBestLapCliffs`
и сохранение обоих старых результатов катеров. Проверки резервного восстановления сравнивают состояние
целиком со свежезаписанной искусственной копией.

## Интеграция и границы

- Из `park-review3` должны прийти `AQUA_COURSE = pick(2, () => 3)`, `SkillRoomHooks.course` и пятый аргумент
  `applySkillFinish(..., course)`. В `racing-review3` эти исходники режима ещё не переносились при выполнении
  узких тестов: тесты выполнялись Node, окончательный typecheck нужен после сборки общего пакета.
- Общий `check/test/build`, браузер профиля и проверка нормализации **копии** фактического сохранения — у ведущего
  перед релизом. Флаги на боевом сервере этим пакетом не включаются.
- Возврат к прежнему курсу в новом Store сохраняет архивы. Откат к старому коду Store, который не знает новые
  поля, требует совместимой пары кода и данных: прежняя нормализация неизвестные поля отбрасывает.

Исходники: `shared/economy.ts`, `server/store.ts`, `server/hub.ts`, `server/lobby/room.ts`, `client/ui/records.ts`.
Точечные обновления прежних fixtures — `test/aqua.test.ts`, `test/hub.test.ts`, `test/expansion-hub.test.ts`.
