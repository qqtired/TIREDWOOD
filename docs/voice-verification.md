## Измерение звука

До нажатия «Разрешить микрофон» число getUserMedia-вызовов — **0**. Затем каждое окно получило свой синтетический 440 Hz WebAudio stream. Настоящий микрофон не открывался, разрешения ОС/браузера не выдавались. Кодек на обоих концах — `audio/opus`; один согласованный audio transceiver с `mid=0`, `sendrecv`, правильным sender на каждом конце.

RMS — уровень сигнала, измеренный анализатором после настоящего пользовательского графа громкости. После анализатора добавлен только тестовый нулевой gain, поэтому физические динамики не воспроизводили тестовый тон.

| Сценарий | RMS на принимающей стороне |
|---|---:|
| A удерживает V → B | 0.056209 |
| A отпускает V → B | 0 |
| B удерживает V → A | 0.056360 |
| Громкость A 50% | 0.028043 |
| Заглушён конкретный собеседник | 0 |
| Выключен входящий голос | 0 |
| Общий mute игры | 0 |
| Входящий звук восстановлен | 0.056790 |
| B отпускает V → A | 0 |

При A→B декодировано 99 360 сэмплов, при B→A — 202 080 к моменту замера. Пакеты и сэмплы продолжают считаться при тишине — PTT не обещает отсутствие сетевого трафика. Поле native `totalAudioEnergy` в этом браузере оставалось нулевым; подтверждение звука опирается на положительный **измеренный RMS** и декодированные сэмплы, не на этот счётчик.

Проверены фактические обработчики Input/App: KeyV, keyup, blur, pause, chat, native dialog и открытая примерочная. Во всех сценариях завершения `track.enabled=false` и `transmitting=false`; новое нажатие в примерочной также заблокировано. После выхода из голоса: track `ended`, peer `closed`, AudioContext `closed`, HTMLAudioElement остановлен и `srcObject=null`. Отказ getUserMedia показывает ошибку, сохраняет возможность слушать и не включает передачу.

## Ограничения доказательства

- Встроенный браузер Codex не дал обычный pointer lock. Для проверки клавиш использовались KeyboardEvents через штатные обработчики и временный shim доступности pointer lock.
- Сигнальные сообщения, SDP и ICE доставлялись корректно, однако обычные host/mDNS и STUN-кандидаты в IAB не завершили ICE. Точная причина окружения не установлена. Для локального media proof адрес **только host ICE** временно заменялся на loopback в браузерном тестовом send-wrapper. RTP/DTLS/Opus, server routing, аудиодорожки, decoder и gain graph оставались настоящими. Такой wrapper **не добавлен в код игры**.
- Эти подмены, синтетические потоки и изменения аудиографа удалены reload/закрытием тестовых окон. В оставленном preview их нет.
- Не проверены физический микрофон и динамики, эхо/шумоподавление, два устройства, WAN/NAT/firewall, forced TURN, Firefox/Safari и одновременный звук шести игроков. Перед включением для всех нужна короткая проверка двух обычных desktop-браузеров через HTTPS и тест TURN там, где прямое соединение не проходит.
- Стандартный `tools/release/csp-check.mjs` сам управляет браузером через отдельный CDP; вместо него выполнена проверка собранного клиента через разрешённый CUA/CDP, с тем же `csp-proxy.mjs`, реальным заголовком и дополнительными голосовыми сценариями. Это не запуск исходного smoke-скрипта.
- Общие дефекты S1–S6 из [передачи Opus](../../OPUS-GAME-STABILITY-OPTIMIZATION-2026-10-03.md) этой функцией не закрыты; полный production-релиз игры данным отчётом не подтверждается.
