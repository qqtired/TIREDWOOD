# Лобби с мини-играми: спецификация

Дата: 1 октября 2026. Владелец одобрил направление: «давай первые 3 пункта выполним сразу по очереди», плюс игровые автоматы в лобби. Валюта: вариант А («жетоны»). После этого владелец написал: «спланируй и начинай работу».

## 1. Коротко

На https://game.tired.solutions вместо одного пейнтбола будет общее место встречи: вечерняя набережная у моря. Там друзья ходят своими желейками, болтают, крутят игровые автоматы и отсюда уходят в игры.

Выпуски, по порядку:

1. **Набережная + скины + пейнтбол от третьего лица + игровые автоматы.** Вход по нику: игра запоминает тебя в этом браузере. Желейку можно наряжать: цвет, узор, глаза, шапка, аксессуар. В её же наряде ты играешь в пейнтбол. Пейнтбол становится игрой от третьего лица: камера за плечом. Пять автоматов «однорукий бандит» с разными ставками. Их барабаны, выигрыши и джекпот видят все, кто рядом.
2. **Дурак за столиками кафе** на набережной: подкидной и переводной, чат, помидоры, колпак дурака.
3. **Гонки на картах** по порту: 3 круга, до 6 участников, боты, бонусы.

Жетоны — одна валюта на всё. Их дают за игры и ежедневный бонус, тратят на автоматы и наряды. Реальных денег нет и не будет.

Каждый выпуск выкладывается отдельно, только после «да» владельца, и проверяется с друзьями.

## 2. Что увидит игрок (выпуск 1)

1. Открывает сайт. Экран входа на фоне набережной (камера медленно облетает её).
   - Первый раз: поле «Как тебя звать?» и кнопка «Играть». Ник уникальный.
   - Потом: «Привет, Боцман!» и кнопка «Играть». Мелкие ссылки: «Другой профиль» и «У меня есть код».
2. «Играть» → мышь захватывается, игрок стоит на площади набережной. Камера сзади, за спиной желейки.
   - Раз в день приходит бонус: «Ежедневный бонус: +50 жетонов».
   - Жетоны видны в правом верхнем углу.
3. Вокруг:
   - **Север:** павильон с автоматами, склад №3 (вход в пейнтбол, над воротами экран с идущим матчем), гараж картинга с табличкой «Скоро».
   - **Восток:** кафе «Чайка» с террасой и столиками. В выпуске 1 за них можно просто сесть.
   - **Запад:** ларёк «Примерочная» с зеркалом, там переодеваются.
   - **Центр:** площадь с доской почёта, батутами, скамейками, фонарями и гирляндами.
   - **Юг и запад:** море. С края можно упасть в воду: плюх, и ты снова на площади.
   - На юго-западе мостки к маяку.
4. Подходишь к предмету — внизу подсказка «E — …». E у автомата — встаёшь к нему, ЛКМ или пробел крутит, шаг (W/A/S/D) — отойти. E у ларька — открывается примерочная. E у ворот склада — переход в пейнтбол.
5. Клавиши 1–4 — эмоции (помахать, танец, «устал», смех). Enter — общий чат на весь сайт. Сообщение ещё и висит облачком над головой. Tab — кто где сейчас.
6. В пейнтболе всё как раньше, но от третьего лица. Q — сменить плечо. Твоя желейка в твоём наряде, команду видно по цветному поясу, баллону маркера и подсветке. В конце раунда видно, сколько жетонов заработал. Выход — Esc → «Выйти на набережную».

## 3. Устройство

### 3.1 Общая схема

Один сайт, один процесс Node, одно WebSocket-соединение на игрока. Игрок в каждый момент находится ровно в одной «комнате»: набережная или пейнтбол, позже — гонка. Дурак — часть набережной, отдельной комнаты у него нет.

Основа — нынешний код Game Opus. Детерминированная физика `stepPlayer`, предсказание своего движения, интерполяция чужих, компенсация лага и бинарные снимки проверены на плейтесте. Их переиспользуем, а не пишем заново. Colyseus, Rapier и базу данных не берём: для компании из 5–30 человек они не нужны.

### 3.2 Сервер

| Модуль | Что делает |
|---|---|
| `server/main.ts` | HTTP (статика, `/health`, Vite в разработке), приём WebSocket, передача соединений в Hub |
| `server/hub.ts` | Hub: соединения, вход, профили, переходы между комнатами, общий чат, список «кто где», общий цикл 60 тиков/с |
| `server/store.ts` | хранилище (JSON-файл, раздел 5) |
| `server/profiles.ts` | профили: создание, вход по ключу и коду, ники, жетоны, покупки, наряд |
| `server/lobby/room.ts` | комната «Набережная»: движение, взаимодействия, эмоции, места, снимки |
| `server/lobby/slots.ts` | зал автоматов: занятость, вращения, общий банк джекпота |
| `server/paintball/game.ts` | нынешний `Game` почти без изменений + наряды, прицел от третьего лица, награды |
| `server/paintball/bot.ts`, `nav.ts`, `lagcomp.ts` | переезжают как есть |

Интерфейс комнаты:

```ts
interface Room {
  readonly kind: 'lobby' | 'paintball';
  join(c: Client): boolean;          // false — нет мест
  leave(c: Client): void;
  onInputs(c: Client, inputs: Input[], count: number): void;
  onMessage(c: Client, msg: ClientMsg): void;   // сообщения, которые Hub не обработал сам
  step(): void;                      // один тик (1/60 с)
  readonly humans: number;
}
```

`Client` — объект соединения:
- профиль;
- текущая комната;
- `epoch` (номер перехода, 0–255);
- пинг;
- `sink` (`sendBinary`, `sendJson`, `close`);
- счётчики для ограничений частоты.

Цикл: один таймер на 60 Гц с догонянием, как сейчас. Каждый тик шагаются комнаты, где есть люди. Если людей нет нигде, цикл спит. У каждой комнаты свой счётчик тиков.

Переход между комнатами (`hub.move(c, room)`):
1. `oldRoom.leave(c)`;
2. `c.epoch = (c.epoch + 1) & 255`;
3. отправить `{t:'scene', scene, epoch}`;
4. `newRoom.join(c)`: комната первым делом шлёт своё приветствие (`lobby` или `welcome`), затем снимки.

Пакеты ввода несут `epoch`. Hub выбрасывает ввод со старым `epoch`, чтобы нажатия, отправленные ещё в пейнтболе, не попали на набережную. Сервер шлёт сообщения по одному соединению в порядке отправки. Поэтому снимкам `epoch` не нужен: всё, что пришло после `scene`, относится к новой комнате.

### 3.3 Клиент

| Модуль | Что делает |
|---|---|
| `client/app.ts` | оболочка: экран входа, соединение с автопереподключением, переключение сцен, пауза и настройки, общие элементы интерфейса (жетоны, чат, уведомления, «кто где») |
| `client/net.ts` | `Connection` (одно на всё время), `ClockSync` (с параметром `minDelay`) |
| `client/lobby/*` | сцена набережной: мир, автоматы, эффекты, облачка чата, эмоции, примерочная |
| `client/paintball/*` | сцена пейнтбола: бывший `session.ts`, `hud.ts`, `slot.ts`, камера от третьего лица |
| `client/render/renderer.ts` | один общий `WebGLRenderer` на все сцены: размер, качество |
| `client/render/world.ts` | мир «Причал»: принимает общий рендерер, небо и море можно перекрашивать |
| `client/render/avatar.ts` | желейка + наряды |
| `client/ui/*` | экран входа, профиль, жетоны, уведомления, список «кто где», примерочная |

Интерфейс сцены:

```ts
interface Scene {
  enter(): void;
  exit(): void;
  onJson(msg: ServerMsg): void;
  onSnapshot(buf: ArrayBuffer, at: number): void;
  frame(now: number, dt: number): void;   // тики ввода 60 Гц — внутри, как сейчас
  onKey(code: string, down: boolean, e: KeyboardEvent): boolean;
}
```

Правила:
- Сцена набережной создаётся при старте (она же фон экрана входа) и живёт всё время.
- Мир «Причал» строится при первом входе в пейнтбол и остаётся в памяти.
- При смене сцены экран на 0,25 с уходит в чёрное.
- После переключения один раз ставится `renderer.shadowMap.needsUpdate = true`, чтобы пересчитались статические тени новой сцены.
- Захват мыши: при ходьбе и в пейнтболе мышь захвачена. В примерочной, меню и паузе отпущена. У автомата и сидя остаётся захваченной: у автомата ЛКМ — крутить, сидя мышь вращает камеру.

### 3.4 Протокол (версия 2)

`PROTOCOL_VERSION = 2`. Бинарные форматы:

- **Ввод:** `[MSG_INPUT=1, epoch u8, count u8, записи по 19 байт]`. Запись та же, что сейчас.
- **Снимок:** формат `MSG_SNAPSHOT=2` без изменений: заголовок 22 байта, точное своё состояние 102 байта, сущности по 14 байт. На набережной байты сущности `hp` и `armor` означают «действие» и «аргумент действия» (раздел 9.5). Поля заголовка про раунд там нули.

JSON от клиента:

| Сообщение | Где | Смысл |
|---|---|---|
| `hello {v, key, nick?, code?, smoke?}` | вход | раздел 4 |
| `chat {text}` | везде | общий чат, в пейнтболе ещё команды `/restart` и т. п. |
| `ping {c}` | везде | замер пинга |
| `use {id}` | набережная | взаимодействие с предметом `id` |
| `unuse {}` | набережная | отойти от автомата, встать, закрыть примерочную |
| `emote {e}` | набережная | эмоция 1–4 |
| `spin {}` | набережная | крутить автомат, у которого стоишь |
| `outfit {o}` | набережная (примерочная) | надеть наряд |
| `buy {item}` | набережная (примерочная) | купить вещь и надеть |
| `rename {nick}` | везде | сменить ник |
| `code {}` | везде | получить код для входа на другом устройстве |
| `leave {}` | пейнтбол | выйти на набережную |
| `pull {}` | пейнтбол | рычаг автомата бонусов на разминке (как сейчас) |

JSON от сервера (новое; сообщения пейнтбола `welcome`, `roster`, `ev`, `slot`, `round`, `pong` остаются):

| Сообщение | Смысл |
|---|---|
| `me {pid, nick, tokens, owned, outfit, stats, build}` | профиль после входа и после изменений |
| `tokens {n, delay?}` | новый баланс; `delay` мс — показать позже (выигрыш на автомате — когда остановятся барабаны) |
| `toast {text}` | всплывающее уведомление (ежедневный бонус, награда за раунд, ошибки покупки) |
| `scene {scene, epoch}` | переход в другую комнату |
| `lobby {id, tick, players, machines, pool, pb, honor}` | приветствие набережной |
| `lroster {players}` | состав набережной: `{id, pid, nick, o}` |
| `outfitOf {id, o}` | кто-то переоделся |
| `lev {e}` | события набережной: всплеск, эмоция, облачко чата |
| `slotSpin {m, id, nick, reels, win, jackpot, item?}` | кто-то крутит автомат `m`, результат — сразу. Клиенты доигрывают анимацию |
| `pool {n}` | банк джекпота |
| `pb {phase, left, scores, humans, names}` | что сейчас на складе (для экрана над воротами) |
| `honor {rich, wins, lastJackpot}` | доска почёта |
| `chat {from, pid, room, team, text, sys}` | сообщение общего чата |
| `chatlog {list}` | последние 30 сообщений при входе |
| `online {list}` | кто где: `{nick, room}` |
| `code {code, until}` | код для входа на другом устройстве |
| `restart {}` | сервер уходит на перезапуск |
| `error {text, code?}` | ошибка. Коды: `version`, `need_nick`, `nick_taken`, `bad_nick`, `bad_code`, `replaced`, `full`, `rate` |

Коды закрытия соединения:
- **4001** — вошёл в другом окне. Клиент сам не переподключается, иначе две вкладки будут выбивать друг друга.
- **4002** — старая версия. Клиент один раз перезагружает страницу; защита от петли через `sessionStorage`.
- **1012** — перезапуск сервера. Автопереподключение.
- **1006** — обрыв связи. Автопереподключение.

## 4. Профили и вход

Ключ устройства:
- 16 случайных байт в base64url.
- Создаётся в браузере при первом входе и лежит в `localStorage['opus.key']`.
- Сервер хранит только SHA-256 ключа. Сам ключ не пишется ни в файлы, ни в журнал.

Вход (`hello`):
1. `v` не совпадает с версией протокола → `error {code:'version'}` и закрытие 4002.
2. Есть `code` → ищем действующий код. Нашли → добавляем хеш ключа к профилю (до 5 ключей, лишний старый удаляется), вход. Не нашли → `bad_code`.
3. Хеш ключа есть у профиля → вход в этот профиль. `nick` игнорируется.
4. Иначе есть `nick` → проверка и создание профиля с 100 жетонами. Ник занят → `nick_taken`, ник плохой → `bad_nick`.
5. Иначе → `need_nick`: клиент показывает поле ника.

Правила ника:
- 2–16 символов: буквы, цифры, пробел, `_ - .`; хотя бы одна буква.
- Уникален без учёта регистра, «ё» считается как «е».
- Заняты имена ботов пейнтбола и служебные: «Система», «Бот», «Админ», «Проверка».

Сменить ник можно в профиле (Esc → «Профиль»), не чаще раза в минуту.

Одно соединение на профиль. Если профиль входит второй раз, старое соединение получает `error {code:'replaced'}` и закрывается с кодом 4001.

Код для другого устройства:
- Профиль → «Код для входа» → 8 символов вида `K7QM-X2PA`.
- Алфавит без похожих знаков: `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`.
- Действует 10 минут, одноразовый.
- На другом устройстве: «У меня есть код».

Ежедневный бонус начисляется при входе, если сегодня по Москве (UTC+3) его ещё не было.

Проверочный вход для выкладки (`smoke`):
- Сервер при первом запуске создаёт `DATA_DIR/smoke-token`: 32 случайных байта, права 0600.
- Если `hello.smoke` совпадает с этим токеном, сервер пускает временный невидимый профиль «Проверка». Его нет в файле, в «кто где» и в чате.
- `deploy/install.sh` запускается от root, читает файл и передаёт токен в `smoke.ts`.

## 5. Хранилище

JSON-файл `DATA_DIR/state.json`:
- `DATA_DIR` по умолчанию `./data`.
- На сервере `/var/lib/game-opus`: в службу добавляются `StateDirectory=game-opus` и `Environment=DATA_DIR=/var/lib/game-opus`. Нужно из-за `ProtectSystem=strict`.
- Всё держится в памяти.

Запись:
- Изменения помечают файл «грязным».
- Через 1 с сохранение: временный файл → `fsync` → `rename`. Файл никогда не остаётся наполовину записанным.
- Раз в сутки при первом сохранении дня делается копия `backups/state-ГГГГ-ММ-ДД.json`, хранятся 7 последних.
- На `SIGTERM` и `SIGINT` — синхронное сохранение.

Чтение при старте:
- Нет файла → пустое состояние.
- Файл битый → он переименовывается в `state.json.corrupt-<время>`, загружается самая свежая копия, в журнал пишется громкое предупреждение.

Схема (версия 1):

```ts
interface State {
  v: 1;
  nextId: number;
  jackpot: number;                 // банк джекпота (дробный, показывается целым)
  lastJackpot: { nick: string; win: number; at: number } | null;
  profiles: Profile[];
}
interface Profile {
  id: number;
  nick: string;
  keyHashes: string[];             // sha256(ключ) в hex, до 5
  createdAt: number;
  lastSeen: number;
  tokens: number;
  owned: string[];                 // купленные и выигранные вещи ('h:tophat', 'p:gold'…)
  outfit: Outfit;
  daily: string;                   // 'ГГГГ-ММ-ДД' последнего бонуса (Москва)
  stats: {
    pbRounds: number; pbWins: number; pbKills: number; pbMvp: number;
    spins: number; slotWon: number; bestWin: number; jackpots: number;
  };
}
```

Коды входа и частоты запросов живут только в памяти.

## 6. Жетоны

Все числа — в `shared/economy.ts`.

| Что | Жетоны |
|---|---|
| старт нового профиля | 100 |
| ежедневный бонус | +50 |
| пейнтбол: доиграл раунд (≥ 60 с в фазе боя) | +10 |
| пейнтбол: за каждого сбитого | +2 (не больше 30 за раунд) |
| пейнтбол: победа команды | +15 |
| пейнтбол: лучший игрок раунда (если лучший — бот, награды нет) | +10 |
| дурак (выпуск 2): доиграл / не дурак / вышел первым | +10 / +10 / +5 |
| гонка (выпуск 3): финишировал / 1-е / 2-е / 3-е место | +10 / +25 / +15 / +10 |
| вещь: обычная / редкая / эпическая | 60 / 150 / 400 |

Награды за раунд пейнтбола:
- Начисляются в конце раунда людям, которые провели в фазе боя не меньше 60 с. Время копится, пока игрок в комнате и идёт бой.
- Итог показывается в финальном окне раунда: «+37 жетонов: раунд 10, сбитые 12, победа 15».
- Игрок, который 90 с ничего не нажимал, отправляется на набережную. Так нельзя стоять в пейнтболе и копить жетоны.

## 7. Скины

### 7.1 Наряд

```ts
interface Outfit { c: number; c2: number; p: string; e: string; h: string; a: string }
// c, c2 — цвет тела и второй цвет узора (индексы палитры 0–15)
// p — узор, e — глаза, h — шапка, a — аксессуар
```

Палитра (все цвета бесплатные): клубничный, малиновый, вишнёвый, апельсиновый, лимонный, лаймовый, мятный, бирюзовый, голубой, черничный, сливовый, лавандовый, розовый, карамельный, шоколадный, молочный.

Каталог (`shared/outfit.ts`). Цены: «бесплатно»; обычная 60; редкая 150; эпическая 400; «джекпот» — только с автомата; «системная» — выдаёт игра.

| Слот | Вещи |
|---|---|
| Узор `p` | нет (бесплатно), тельняшка, горошек, пятна (обычные), закат-градиент, камуфляж (редкие), сахарная обсыпка (эпическая), золото (джекпот) |
| Глаза `e` | обычные, сонные, сердитые, довольные (бесплатно), очки (обычные), тёмные очки, пиратская повязка (редкие), монокль (эпический) |
| Шапка `h` | нет, кепка (бесплатно), панама, ушанка, рыбацкая шляпа, бандана (обычные), каска, бескозырка (редкие), цилиндр (эпический), корона (джекпот), колпак дурака (системная, выпуск 2) |
| Аксессуар `a` | нет, шарф (бесплатно), усы, бабочка (обычные), наушники, спасательный круг (редкие), золотая цепь (эпическая), погоны (системная, выпуск 2) |

Правила:
- Надеть можно только свои или бесплатные вещи. Сервер проверяет каждый наряд, неверные поля заменяет на вещи по умолчанию.
- Наряд по умолчанию для нового профиля: случайный цвет, без узора, обычные глаза, кепка, без аксессуара.
- Боты пейнтбола получают случайный бесплатный наряд, зависящий от их номера.

### 7.2 Отрисовка

Тело:
- Материал желе прежний, к нему добавлены униформы `uPattern` (номер узора), `uColor2` и `uMetal`.
- Узоры считаются в шейдере по координатам тела. Картинки не нужны, программа шейдера одна на всех, число вызовов отрисовки не растёт.
- Как выглядят узоры:
  - тельняшка — горизонтальные полосы по высоте;
  - горошек — точки по сферической сетке;
  - пятна — порог 3D-шума;
  - закат — градиент снизу вверх;
  - камуфляж — два порога шума;
  - сахар — мелкие блёстки по хешу, заметны на свету;
  - золото — металл, золотой цвет, низкая шероховатость.

Шапки и аксессуары:
- Маленькие меши из примитивов. Геометрия общая, материалы общие на тип.
- Крепятся к узлу тела, двигаются с наклоном макушки, как сейчас «шапочки» команд.

Глаза:
- Меняется форма век (сонные, сердитые, довольные).
- Очки, тёмные очки, повязка и монокль — отдельные меши.

В пейнтболе команда видна по четырём признакам:
- пояс цвета команды на талии (тор);
- баллон маркера цвета команды;
- подсветка по краю тела цвета команды;
- цвет таблички с ником.

Нынешние «шапочки» команд (чашелистик и листик) убираются.

На набережной маркера нет. Руки-варежки появляются только в эмоциях и у автомата.

## 9. Набережная: как всё работает

### 9.1 Движение и камера

Движение — тот же `stepPlayer` без стрельбы (`canFire = false`): бег, прыжок, рывок, батуты.
- Сервер симулирует 60 тиков/с, снимки шлёт 30 раз в секунду.
- Своё движение клиент предсказывает (`Predictor`), чужих интерполирует (`RemoteTrack`).
- `ClockSync.minDelay` для набережной — 2,6 тика.
- Упал в воду (`y < DROWN_Y`): событие «плюх» и появление на площади. Идёт сброс состояния (`SNAP_SELF_RESET`).

Камера — от третьего лица, общая функция `cameraRig` из `shared/aim.ts` (раздел 11):

| Режим | Камера |
|---|---|
| набережная | центр над головой, 3,6 м назад, 0,6 м вверх; колесо мыши 2–6 м |
| у автомата | фиксированный ракурс из-за плеча на барабаны |
| сидя | камера вращается вокруг желейки мышью |
| примерочная | камера перед желейкой, как в зеркале; её можно вращать перетаскиванием |

Во всех режимах камера не залезает в стены.

### 9.2 Взаимодействия

Предмет задаётся так: `{id, kind, x, y, z, r, label}`.

| `kind` | Что делает | Подсказка |
|---|---|---|
| `slot` (5 шт.) | встать к автомату `m` | «E — сыграть (ставка 5)» |
| `pb_gate` | перейти в пейнтбол | «E — в пейнтбол» или «Склад переполнен» |
| `garage` | только сообщение | «Картинг откроется скоро» |
| `kiosk` | открыть примерочную | «E — примерочная» |
| `seat` (стулья, скамейки) | сесть | «E — сесть» |
| `honor` | подсказка | «Доска почёта» |

Клиент подсвечивает ближайший предмет в радиусе `r`, который находится перед игроком.

Сервер проверяет расстояние до предмета: не больше `r + 0,5`. Если место свободно, ставит игроку «действие» и переносит его в точку предмета с нужным поворотом (сброс состояния). Любое нажатие движения или `unuse` освобождает место. Сервер освобождает место и сам: при выходе игрока или если тот ушёл дальше 1,5 м.

### 9.3 Эмоции, облачка, чат

Эмоции (клавиши 1–4):

| Клавиша | Эмоция | Длится |
|---|---|---|
| 1 | помахать | 3 с |
| 2 | танец | до первого шага |
| 3 | «устал»: желейка оседает, глаза сонные, над головой «zzz» | 3 с |
| 4 | смех: трясётся, «ха-ха» | 3 с |

- Не чаще раза в 0,5 с. Движение прерывает эмоцию.
- Анимация на клиенте по байту действия из снимка. Руки-варежки появляются рядом с телом.

Облачко над головой:
- у всех на набережной;
- до 60 символов, длиннее — с «…»;
- висит 6 с; следующее сообщение заменяет предыдущее.

Общий чат:
- Один на весь сайт. У сообщения есть метка комнаты. В чужой комнате перед ником значок: 🏠 — набережная, 🎯 — пейнтбол.
- В пейнтболе ники окрашены в цвет команды, как сейчас.
- При входе приходят последние 30 сообщений.
- Команды пейнтбола (`/restart`, `/bots`, `/skill`, `/team`, `/kill`, `/help`) работают только в пейнтболе.
- Системные строки комнаты («X заходит за Чернику», «Бой!») остаются внутри комнаты.
- Общие системные строки: джекпот и крупный выигрыш (от ×20 ставки).

Tab на набережной — список «кто где»: ник и комната.

### 9.4 Экран склада и доска почёта

- **Экран над воротами** — текстура-холст. Обновляется по сообщению `pb`: раз в секунду, пока в пейнтболе кто-то есть; иначе по изменению. Состояния:
  - «Идёт бой 3:12 · Черника 12 : 9 Мандарин · играют: Боцман, Юнга»;
  - «Разминка»;
  - «Пусто — заходи первым!».
- **Доска почёта** — текстура-холст. Обновляется по сообщению `honor`: при входе, после джекпота и раз в минуту.

### 9.5 Снимок набережной

Сущность — те же 14 байт, что в пейнтболе:
- `id` — номер места игрока в комнате (1–250);
- флаги `E_ALIVE` и `E_GROUNDED`;
- позиция, `yaw` и `pitch` — как в пейнтболе;
- байт `hp` = действие, байт `armor` = аргумент действия.

Действия:
- 0 — нет;
- 1 — помахать;
- 2 — танец;
- 3 — «устал»;
- 4 — смех;
- 5 — сидит (аргумент — номер места);
- 6 — у автомата (аргумент — номер автомата);
- 7 — за столом в дурака (выпуск 2);
- 8 — в примерочной.

Вместимость набережной — 64 человека.

## 10. Игровые автоматы

### 10.1 Математика (`shared/slots.ts`)

- 3 барабана, у каждого независимый взвешенный выбор символа.
- Веса из 32: 🍒 вишня 8, 🍋 лимон 7, 🔔 колокол 6, ⚓ якорь 5, ⭐ звезда 3, 7️⃣ семёрка 3.
- Автоматов 5, ставка у каждого своя: 1, 5, 10, 25, 50 жетонов. Названия по ставке: «Копеечка», «Пятак», «Червонец», «Четвертак», «Полтинник».

| Комбинация | Выплата (× ставки) |
|---|---|
| ровно две вишни (в любых местах) | ×2 |
| три вишни | ×6 |
| три лимона | ×10 |
| три колокола | ×15 |
| три якоря | ×20 |
| три звезды | ×50 |
| ровно две семёрки | ×4 |
| три семёрки — **ДЖЕКПОТ** | ×100 + доля банка |

Цифры проверены полным перебором всех 32 768 комбинаций; тест это закрепляет. Возврат без банка — 87,4 %, выигрыш в 20,3 % вращений, джекпот — 1 раз на 1214 вращений.

Банк джекпота:
- С каждой ставки в банк уходит 5 %.
- Джекпот платит ×100 ставки плюс `банк × ставка / 50`: «Полтинник» забирает весь банк, «Копеечка» — 1/50.
- После выплаты банк не опускается ниже 1000.
- Сверх жетонов джекпот дарит первую ещё не полученную вещь из списка: корона, потом узор «золото».
- Жетоны в сумме медленно утекают: примерно 7,6 % ставок. Так они не обесцениваются.

### 10.2 Сервер (`server/lobby/slots.ts`)

У автомата есть `occupant` (кто стоит), `spinning` (идёт ли вращение) и `readyAt` (когда можно крутить снова).

`spin` от игрока:
1. Проверки: он стоит у этого автомата; автомат свободен; жетонов хватает на ставку.
2. Списать ставку, 5 % отправить в банк.
3. Выбросить 3 символа через `crypto.randomInt` и посчитать выигрыш.
4. Зачислить выигрыш сразу и сохранить профиль.
5. Разослать всем на набережной `slotSpin`.
6. Игроку отправить `tokens {n: после списания}` сразу и `tokens {n: итог, delay: 2400}`.
7. Автомат занят 2,6 с.

Джекпот или выигрыш от ×20 ставки: общая строка в чате, отложенная на 2,4 с (когда барабаны остановятся). После джекпота — рассылка обновлённых `pool` и `honor`.

Отдельный лимит частоты не нужен: автомат не примет новое вращение, пока занят.

### 10.3 Клиент

Автоматы — 3D-модели:
- корпус с закруглённым верхом и лампочками по контуру;
- окно с тремя барабанами — цилиндры с текстурой-лентой символов, нарисованной на холсте;
- рычаг сбоку;
- табличка со ставкой и названием;
- лоток для монет.

Анимация по `slotSpin`:
- барабаны разгоняются и останавливаются в 1,2 / 1,7 / 2,2 с с небольшим «доводом»;
- на 2,4 с — итог;
- рычаг опускается у игрока, который крутит, и у всех, кто это видит.

Эффекты:

| Результат | Что происходит | Где |
|---|---|---|
| проигрыш | лампочки гаснут | у автомата |
| выигрыш | лампочки бегут, монеты сыплются в лоток и разлетаются, звон, над автоматом всплывает «+50» | у автомата |
| крупный выигрыш (от ×20) | больше монет, вспышка | у автомата |
| джекпот | сирена, мигают все автоматы, салют над набережной, табло джекпота мигает, крупная надпись «ДЖЕКПОТ! Боцман +5 000» | везде на набережной |

- Звуки синтезируются, как сейчас: рычаг, треск барабанов, стук остановки, звон монет, сирена, салют. Звук звучит в пространстве: чужой автомат слышно оттуда, где он стоит.
- Табло джекпота над автоматами показывает банк. Банк растёт, когда кто-то ставит.
- HUD у автомата: «ЛКМ / пробел — крутить · ставка 5 · шаг — отойти».

## 11. Пейнтбол от третьего лица

### 11.1 Камера и прицел (`shared/aim.ts`)

Точка опоры камеры — 1,45 м над ногами.

| Режим | Назад | Вбок | Вверх |
|---|---|---|---|
| обычный | 2,9 м | 0,6 м | 0,25 м |
| прицел (ПКМ) | 1,4 м | 0,5 м | 0,15 м |

- Вбок — в сторону выбранного плеча. По умолчанию правое. Q переключает плечо: пока выбрано левое, клиент шлёт флаг `BTN_SHOULDER = 1024` в каждом вводе.
- Столкновения: луч от опоры к камере по боксам мира без прострельных стен. Камера встаёт на 0,2 м ближе точки попадания, но не ближе 0,35 м к опоре.
- Отдача (`recoilP`, `recoilY`) поворачивает и камеру, поэтому прицел в центре экрана честный.

Как считается выстрел:
1. `f` — направление взгляда с отдачей. Луч прицела идёт из камеры вдоль `f`, но начинается на глубине опоры. Так то, что между камерой и желейкой, не мешает.
2. Луч ищет точку `P`: первое попадание в мир или в противника. Если ничего нет — 160 м.
3. Направление выстрела: из глаз (`y + EYE_HEIGHT`) в `P`. Если `(P − глаза)·f < 0,5`, берётся просто `f`.
4. Разброс — тот же детерминированный, что сейчас, но вокруг этого направления.

Сервер повторяет то же самое по вводу игрока (`yaw`, `pitch`, флаги плеча и прицела). Цели откатываются во времени, как сейчас: противники при поиске `P` берутся на тот момент, который видел стрелявший.

Для этого `stepPlayer` отдаёт в событиях выстрела `aimYaw`, `aimPitch`, `spread` и `shots`. Прежние `dirX/Y/Z` остаются для ботов: боты целятся от глаз, камеры у них нет.

Если стена у самого лица перекрывает линию от глаз до `P`, прицел показывает крестик в точке, куда на самом деле прилетит шарик.

### 11.2 Что меняется в клиенте

- Вид от первого лица и маркер в руках (`viewmodel.ts`) убираются.
- Своя желейка видна. Если камера подошла ближе 0,9 м — её не видно.
- Свой шарик вылетает из дула маркера на своей желейке и летит в точку попадания.
- Прицел остаётся в центре экрана с прежней индикацией разброса.
- В прицеле поле зрения сужается в 1,25 раза и работает чувствительность «мышь в прицеле».
- Камера смерти — прежняя. Автомат бонусов на разминке остаётся.
- В паузе появляется кнопка «Выйти на набережную».
- Таблица счёта и финальное окно показывают наряды через цвет ника и заработанные жетоны.

### 11.3 Что меняется в сервере

- `addHuman(profile, sink)`: имя = ник, наряд из профиля.
- В `RosterEntry` добавляется `o: Outfit`.
- Считается время в фазе боя. В конце раунда вызывается `hooks.reward(pid, итог, разбивка)`.
- Обычные сообщения чата уходят в общий чат через `hooks.chat`. Команды и системные строки остаются внутри комнаты.
- Статус для экрана склада — `hooks.status()`.
- Игрок без ввода 90 с отправляется на набережную.
- Мест для людей по-прежнему 16. Полный склад: «Склад переполнен».

## 12. Выкладка и перезапуск

Порядок перезапуска:
1. На `SIGTERM` сервер рассылает `restart`, сохраняет хранилище и закрывает соединения с кодом 1012.
2. Клиент показывает «Сервер обновляется — переподключаемся…» и повторяет попытки через 1, 2, 4, 8… с (не реже раза в 15 с).
3. После переподключения клиент входит автоматически и оказывается на набережной.
4. Если сервер прислал другой `build` (хеш `dist/index.html`), чем был при первом входе, клиент перезагружает страницу и получает свежую версию. В разработке `build = 'dev'`.

`/health` отдаёт `{ok, online, lobby, paintball, busy, stepMs}`. `busy` — сколько людей в пейнтболе прямо сейчас.

`deploy.sh`:
- отказывается выкладывать, только если `busy > 0` (читает `busy ?? humans`, чтобы работать и со старым сервером);
- люди на набережной выкладке не мешают: их перекинет автоматически;
- `FORCE=1` по-прежнему выкладывает принудительно.

Служба systemd: добавить `StateDirectory=game-opus` и `Environment=DATA_DIR=/var/lib/game-opus`.

`smoke.ts`: вход с токеном проверки, ожидание `me`, `scene` и снимка набережной.

`deploy/game.nginx.conf`: в `/ws` добавить `proxy_set_header X-Real-IP $remote_addr;`, чтобы ограничения частоты работали по адресу игрока.
- Сервер доверяет заголовку, только если соединение пришло с 127.0.0.1.
- Nginx меняется вручную по README, отдельно от выкладки и только после «да» владельца.
- Пока заголовка нет, ограничения работают по всему серверу сразу.

Первая выкладка выпуска 1 создаст пустое хранилище. Профили заводятся заново при входе, у нынешней игры профилей нет.

## 13. Защита от злоупотреблений

Всё решает сервер: жетоны, выигрыши, покупки, наряды, дистанции, места. Клиент только показывает.

Ограничения:

| Что | Лимит |
|---|---|
| новые профили | 5 в час с адреса (без адреса — 30 в час на весь сервер) |
| неверные коды входа | 10 в час с адреса |
| чат | 5 сообщений за 5 с (как сейчас) |
| эмоции | 2 в секунду |
| взаимодействия | 4 в секунду |
| смена наряда | 5 в секунду |
| покупки | 2 в секунду |
| смена ника | раз в минуту |
| переходы между комнатами | раз в 2 с |
| общий лимит сообщений (как сейчас) | 300 в секунду |

Проверки ввода:
- ник и чат — нынешними функциями очистки;
- наряд — по каталогу;
- номера автоматов, мест и эмоций — по диапазонам;
- JSON длиннее 2000 символов отбрасывается (как сейчас).

Ключ устройства хранится только в виде хеша, в журнал попадают ник и номер профиля. Токен проверки лежит в файле с правами 0600.

## 14. Производительность

- **Набережная:**
  - статика склеена по материалам, как в «Причале», — несколько десятков вызовов отрисовки;
  - желейки: тело, глаза, шапка, аксессуар — до 5 вызовов на человека;
  - тени от статики считаются один раз.
- **Сеть:** снимок набережной на 30 человек ≈ 22 + 102 + 30×14 ≈ 550 байт, 30 раз в секунду. Для VPS это мелочь.
- **Сервер:** `stepPlayer` дешёвый. 60 тиков × 64 человека по ~200 боксам — единицы миллисекунд в секунду.
- **Качество «Низкое»:** без точечных светильников и без салюта-частиц, только вспышка.

## 15. Проверка

Автотесты (`node --test`):

| Тема | Что проверяем |
|---|---|
| хранилище | сохранение и чтение; запись не бывает наполовину записанной (через временный файл); битый файл → восстановление из копии; дневные копии, хранятся 7 |
| профили | создание; вход по ключу; ник занят, в том числе с «ё»/«е»; вход по коду и одноразовость кода; лимит ключей; ежедневный бонус по московской дате |
| экономика и автоматы | полный перебор: возврат от 85 до 90 %, выигрыш не реже 20 %; расчёт банка и доли; банк не ниже 1000; выдача корону → золото → только жетоны |
| наряды | каталог без повторов; очистка чужих и несуществующих вещей; покупка списывает жетоны и не уходит в минус |
| набережная | хождение и падение в воду с возвратом; проверка дистанции взаимодействий; занятость автомата; вращение без жетонов отклоняется; эмоции сбрасываются движением |
| прицел | `cameraRig` детерминирован и не залезает в стену; точка прицела и запасное направление |
| пейнтбол | тест ботов остаётся; награды в конце раунда только тем, кто был в бою 60 с; наряды в составе |
| Hub | переход между комнатами меняет `epoch` и отбрасывает старый ввод; второй вход в профиль выбивает первый; проверочный вход не сохраняется |
| протокол | ввод с `epoch`; старые тесты физики и снимков |

Проверка в браузере:
- Два окна: разные ники, общий чат, облачка, эмоции.
- Автомат: вращение, выигрыш, джекпот. Для проверки джекпота в режиме разработки есть переменная `DEV_RIG=777`.
- Примерочная: покупка и примерка, наряд виден второму окну.
- Переход в пейнтбол и обратно, камера от третьего лица, попадания.
- Перезапуск сервера → автопереподключение.
