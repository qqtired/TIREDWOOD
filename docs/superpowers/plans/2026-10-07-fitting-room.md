# Примерочная TIREDWOOD — план реализации

**Цель:** отдельная лаборатория для выбора референсов, добавления 3D-моделей,
примерки на настоящей желейке и подготовки вещей и сетов к последующему переносу в игру.

**Задание:** текущая просьба владельца от 7 октября 2026. Назначение — `/fitting-room/`
в отдельном Lab; внутри сборки игры — `/lab/fitting-room/`.

**Архитектура:** отдельная страница Vite/TypeScript, three.js и игровой Avatar.
Данные кандидатов отделены от `shared/outfit.ts`, цен и профилей игроков.
Редактирование сохраняется в браузере; изображения и GLB — в IndexedDB.
Переносимая копия проекта содержит метаданные и локальные файлы. Внешний API генерации
не нужен: Codex генерирует изображения и создаёт модели по выбранным референсам.

## Ограничения

- Девять существующих слотов, без новых игровых механик, сетевого протокола и наград.
- Русский интерфейс, Rubik, уютная приморская стилистика.
- Решение «Готово к переносу» не меняет игровой каталог.
- Сохранить текущие незавершённые изменения Lab и стенда производительности.
- Без коммита, публикации и выкладки до отдельного разрешения владельца.
- Генерация 40 референсов — поддерживаемый будущий сценарий, а не текущая массовая генерация.

## Файлы и интерфейсы

- `shared/fitting-room.ts`: типы `FittingItem`, `FittingSet`, `FittingProject`.
- `client/fitting-room/state.ts`, `catalog.ts`: валидация, каталог игры, кандидаты,
  применение вещей/сетов, задания для ImageGen. Независимый блок агента.
- `client/fitting-room/scene.ts`, `models.ts`: настоящий Avatar, игровые вещи,
  лабораторные фабрики, GLB, вращение, движение, студия и приморская диорама.
  Независимый блок агента. При необходимости точечный метод Avatar для Wear.
- `client/fitting-room/main.ts`, `page.ts`, `storage.ts`, `fitting-room.css`: интерфейс,
  локальное сохранение, импорт/экспорт и сопоставление референса с моделью.
- `lab/fitting-room/index.html`, `tools/fitting-room/vite.config.ts`: отдельный вход и сборка.
- `vite.config.ts`, `package.json`, `client/lab/page.ts`, `docs/README.md`:
  точечное подключение страницы, команд и ссылки, с сохранением чужого diff.
- `docs/fitting-room.md`: как добавлять референсы/модели и переносить выбранное.
- `test/fitting-room-*.test.ts`: реальные проверки состояния и геометрии.

## Последовательность

- [x] Каталог и состояния: загрузка, все слоты, выбор референсов, запрет одобрять
  референс без модели, замена одного слота, атомарное применение сета, проверка цен.
- [x] 3D: игровые вещи и несколько лабораторных моделей, движение и примерка сета,
  GLB с локальными ресурсами, настройка положения/масштаба.
- [x] Интерфейс: поиск, слоты, кандидаты/игра, референс рядом со сценой, карточка вещи,
  редактирование, наборы, цвет тела/узора, выбор состояния.
- [x] Переносимость: импорт пачки изображений, модель к выбранной вещи,
  сохранение после перезагрузки, полная копия проекта и задание на 40 референсов.
- [x] Подключение Lab, отдельная сборка, документация.
- [x] Свежие `npm run check`, `npm test`, `npm run build`, отдельная сборка;
  браузерный сценарий на собранной версии и короткая эмуляция телефона.

## Проверка рисков

- Неверный JSON и цены отклоняются без перезаписи действующего проекта.
- GLB с внешними ссылками не выполняет запросы к чужим адресам.
- Новый референс без модели не обещает 3D-просмотр или готовность к переносу.
- Сет не содержит две вещи одного слота; применение не теряет несвязанные слоты.
- Ошибка локального хранилища видна, экспорт остаётся доступным.

**Готово:** владелец может отобрать изображения, примерить настоящие модели,
собрать сет, отредактировать название/цену и сохранить переносимый проект;
ни одна лабораторная вещь не появляется у игроков.
**Откат:** убрать вход страницы и ссылку Lab; каталог игры и данные игроков не менялись.
