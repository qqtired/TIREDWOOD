# Плавный переход в режимы и обратно (агент `loading`, ветка `rework/loading`)

## Статус / что осталось

Готово и проверено в headless Chrome: экран загрузки, прогрев, ожидание всех, 3-2-1, путь ошибки, все переходы,
телефон (эмуляция 375×812, вход в «Выше облаков» и возврат — карточка влезает, ошибок нет).
`npm run check && npm test && npm run build` — зелёные (975/975). Коммиты в `rework/loading`.

## Решение коротко

**Клиент** (`client/ui/transition.ts`, `client/ui/transition.css`):
- `scene` от сервера → затемнение 0,35 с (старая сцена ещё рисуется, письма новой комнаты копятся в очереди,
  номер перехода `epoch` меняем только после стройки — старый ввод сервер выбросит);
- под непрозрачным экраном: выход из старой сцены, стройка новой, разбор очереди;
- прогрев: один «сухой» кадр ловит пары сцена+камера (`gl.render` подменяется на кадр), `compileAsync`
  для каждой, текстуры заливаются по одной в кадр (`initTexture`, бюджет ~6 мс), потом два настоящих кадра;
- `ready` серверу → проявление 0,4 с, сразу вид от игрока;
- экран: название режима, рисунок (inline SVG), подсказка, полоса прогресса, кто заходит вместе с тобой (✓/…);
- после проявления: плашка «Ждём: …», затем крупный отсчёт 3-2-1 по письму сервера `go` (в картинге свой отсчёт);
- 15 с без готовности или ошибка стройки → понятное сообщение, `leave`, плавный возврат в город.

**Сервер** (`server/readygate.ts`, `shared/loading.ts`):
- хаб после `move` записывает игрока в «загружается» (кроме набережной); `{t:'ready', e}` снимает;
- пока в комнате кто-то грузится (не дольше 8 с), её отсчёт перед стартом стоит: `prestart.phaseEnd++` каждый тик;
- у комнаты одна строка — геттер `prestart` (решётка, вступление, сбор, разминка; null — сейчас нечего держать);
- письма `{t:'load', who, wait}` всем в комнате при изменениях, `{t:'go', ms}` за 3 с до старта;
- `PROTOCOL_VERSION` 13;
- dev-команда `/go <режим>` (только `--dev` или `DEV_GO=1`) — для проверки переходов без прогулки по набережной.
