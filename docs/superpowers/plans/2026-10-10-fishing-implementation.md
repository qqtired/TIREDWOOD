# Рыбалка: внедрение острова «Последний свет», лодок и способностей (10.10.2026)

Владелец одобрил страницу ревью (https://tired.solutions/tech/tiredwood-fishing/, исходник `lab/fishing-review/`)
и ответил на вопросы. Всё выходит **одним релизом** вместе с уже влитыми хотфиксами. Ведущий сливает пакеты в
`mode/fishing`; в `main` — только по «да» владельца.

Дизайн — источник правды:
- `docs/superpowers/plans/2026-10-10-fishing-island.md` и `.json` — лодки, стоянка, мир, остров, 20 видов, экономика, косметика;
- `docs/superpowers/plans/2026-10-10-fishing-abilities.md` — способности, +20 % времени, награды уровней 1–15;
- `docs/superpowers/plans/2026-10-10-fishing-island-reel.json` — калибровка и способности рыб острова;
- ассеты: `lab/fishing-review/models/` (лодки, пирс), `models/island/`, `cosmetics/`, `img/fish/`, `img/isle-*.webp`.

## Решения владельца (10.10, после ревью)

1. Мифики на 0-м уровне ловятся в 3 % — оставить.
2. Осётр «у дна» 100 % — починить одной строкой (`waryHold`/WARY, как у легенд острова).
3. Пятый дом на острове — оставить копию.
4. Зубы Плащеносной акулы щёлкают.
5. Способности рыб острова — мягче первого наброска (как в island-reel.json).
6. «Спокойная рука» и быстрая подсечка — оставить.
7. **Радио на лодке:** звуковая система, управляет владелец лодки или он разрешает всем; 3 станции — быстрая
   агрессивная для езды (в духе Need for Speed), спокойная для ловли и третья на выбор ведущего; бесконечные треки
   по кругу без слов.
8. **Лайвел (садок) в лодке:** 25 / 50 / 75 мест (Волжанка / Альбакор / Нортсильвер). Рюкзак полон — рыба идёт
   в лайвел. Продать торговцам можно прямо из лодки. Сидишь в чужой лодке — при полном рюкзаке рыба грузится в лайвел
   **твоей** лодки. Лодки нет — при полном рюкзаке ловить дальше нельзя (как сейчас).

Решения ведущего по деталям: лайвел — у игрока по лучшей купленной лодке (вместимость по ней); «продать из лодки» —
в окне любого скупщика (Семён, Саня, Игнат) продаётся и рюкзак, и лайвел; плюс кнопка «Продать улов» в меню своей
лодки, когда она стоит у стоянки или у причала острова. Радио — синтез на клиенте тем же движком, что музыкальный
автомат (`client/music/`), сервер хранит только станцию/вкл/разрешение.

## Флаги

- Способности, +20 % времени, награды уровней, осётр — без нового флага, под `FISH2` (одобрено).
- Острова, лодки, лайвел, радио, косметика острова, −60 % цен (`FISH_PRICE_CUT` 0.65 → 0.4) — новый флаг `ISLE`
  в `server/main.ts`: без переменной — только с `--dev`, нужна `FISH2`. Без флага игра ровно как сейчас (с хотфиксами).

## Контракты между пакетами (чтобы не ждать друг друга)

- **Место ловли** (D владеет): `FishZone = 'pier' | 'barkas' | 'isle'`; `shared/fishisle.ts` (D) экспортирует
  `ISLE_CENTER` (−2364.9, 557.6 по x, z), `ISLE_WATERS_R = 300`, `fishZoneAtSea(x, z): 'barkas' | 'isle'`.
  B зовёт её для ловли с якоря; C — для мест ловли на моле (всегда `'isle'`).
- **Лодки** (B владеет): `shared/fishboat.ts` — `BOATS` (id `volzhanka|albakor|northsilver`, уровень, цена, скорость,
  разгон, `livewell` 25/50/75, эхолот −5/−10/−15 % ожидания поклёвки, якорь с), профиль `fish.boats: string[]`
  (купленные). D читает вместимость лайвела отсюда; если файла ещё нет у D — заглушка с теми же именами.
- **Лайвел** (D владеет): профиль `fish.livewell: BagFish[]` и функции в `shared/fishlivewell.ts`;
  сервер — `server/lobby/fishlivewell.ts`. B вызывает только «продать улов из лодки» (одна функция D).
- **Остров в мире** (C владеет): `shared/maps/isle.ts` — точки причала/мола/Игната/спавна из `props-layout.json` и
  Empty-точек GLB; B берёт оттуда точки бертов причала острова.
- **Радио** (F владеет): `shared/boatradio.ts`, `client/boat/radio*.ts`; B даёт хук «лодка игрока создана/удалена» и
  место кнопки в меню лодки. Если хука нет — F добавляет точечное подключение сам и пишет об этом в отчёте.
- **Общие файлы** (`client/app.ts`, `client/lobby/scene.ts`, `server/hub.ts`, `server/lobby/room.ts`, `shared/messages.ts`,
  `shared/maps/lobby.ts`, `shared/constants.ts`, `server/main.ts`) — только короткие точечные подключения, перед правкой
  перечитать; новые сообщения — новыми типами в JSON без смены формата там, где можно. `PROTOCOL_VERSION` поднимает
  только A (до 16), остальные его не трогают.
