# Голос по удержанию V — первая реализация

Статус: локальный MVP завершён; gate 843/843, native Opus audio proof и VOICE=0 проверены. Ограничения IAB/loopback и внешней приёмки зафиксированы в docs/voice-verification.md. Пользователь попросил сделать рабочий вариант после исследования, с возможностью отката. В контексте «TTS/touch to speak» означает живой голос, PTT. Визуальные изменения предыдущего прохода и текущий аудит сохранены. Production не меняется.

## Решение

WebRTC/Opus, до 6 добровольно подключившихся участников в текущей серверной комнате. Это ограниченная голосовая группа, без proximity/SFU. Игровой WS передаёт только адресное согласование, без аудиочанков. VOICE: production по умолчанию off, DEV on; VOICE=0 выключает функцию. Никаких изменений профилей или экономики.

Отдельный вход в голос и явное разрешение микрофона. Удержание V передаёт; отпускание, blur, скрытие страницы, меню/чат, переход комнаты и обрыв немедленно выключают передачу. Полное выключение/выход останавливает дорожки и закрывает peer connections. Громкость входящего голоса и mute собеседников; микрофон и динамики имеют отдельные состояния.

Нативный mono/echoCancellation/noiseSuppression/autoGainControl; предпочтение Opus, maxBitrate 32000 при поддержке. Детерминированный offerer по назначенному сервером voice-id; новый id после перехода/переподключения исключает старые SDP/ICE. Сервер проверяет авторизацию, действительную room identity, ёмкость, self/to, размер и бюджет сообщений. Для voice control при заполнении очереди — явный разрыв вместо потери критического сообщения.

Public STUN по умолчанию, настраиваемый список; опциональный TURN с серверным HMAC-secret и временными credentials. Секрет не попадает в bundle/логи. TURN/SFU/порты на production не создаются. Внешний NAT/relay остаётся отдельной проверкой. В UI при включении указать прямое соединение с участниками; никаких записей или транскрипции.

## Владельцы

- root: контракт shared/voice.ts, App/Hub/main/messages/constants, документация и интеграция.
- fortress_expansion_astra: новые server/voice.ts + voice-config.ts, server regressions.
- blackjack_core_astra: client/voice.ts — RTC/media/PTT lifecycle, тесты с управляемыми зависимостями.
- blackjack_ui_astra: client/ui/voice.ts + CSS, доступные органы управления, без записи общих файлов.

Сабагенты Astra High; последовательные общие интеграции только root.

## Границы готовности

Локальная рабочая реализация должна быть доказана реальным RTCPeerConnection и декодированным синтетическим аудио, а не одними mocks. Два устройства/WAN/forced TURN/физический микрофон — отдельная непроверенная граница, если недоступны. Известные дефекты S1–S6 из общего аудита остаются отдельной работой для Opus; не выдавать этот MVP за готовый production-релиз.

Откат: VOICE=0 на новой согласованной сборке и restart; клиентская UI не появляется, media не запрашивается. Для полного исходного отката использовать список файлов и сохранённый pre-voice manifest; не восстанавливать старые профили/сериализатор.
