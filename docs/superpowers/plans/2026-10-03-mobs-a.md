## Договор: что добавлено (ничего не убрано и не переименовано)

- `MOB_STRIDE = 1.25` — метров на цикл шага (`anim.gait`); `ARMY` — цвета войска (варенье, глаза).
- `MobAnim.flags?` — признаки `ZF_*` из снимка (щит цел, бочка, светится, экипаж, ступень).
- `MobAnim.stage?` — байт `stage` снимка как есть: у босса фаза 1…3, у щупальца номер, **у лодки — сколько экипажа ещё в ней**.
- `MobDef.when?` — **особый вариант** только для особей с признаками `ZF_*` (экипаж лодки — `ZF_CREW = 8`): обычным
  особям вида он не достаётся, у особи с признаками выбирается вместо обычных (между собой — по `weight`).
- `pickVariant(defs, kind, seed, flags = 0)`; вес 0 (и отрицательный, NaN) не выбирается никогда.
- `setChild`/`setChildS` — кость относительно родителя; `mobMaterial(glow)` — материал с вспышкой, оттенком и точными
  нормалями инстансов; `buildPreview(def)` — одна модель без инстансов (стенд, превью).
- Масштаб корня и костей может быть неравномерным (босс в воротах): нормали считаются точно (кофактор матрицы
  инстанса вместо приближения three.js). Не ноль и не зеркало — бери ≥ 0,02.

## API рендерера (`client/fort/mobs/renderer.ts`)

```ts
const mobs = new MobRenderer(scene, ALL_MOBS, quality);   // { castShadow?: false } — в крепости тени не отбрасывать
mobs.setQuality(q, slow);        // тени по качеству; на «низком» у вида один (самый частый) вариант
mobs.setFogGlow(on);             // морской туман: глаза и огоньки сквозь туман
mobs.has(kind, flags?)           // есть ли модель
mobs.variant(kind, seed, flags?) // какая MobDef нарисует особь (тот же выбор, что pickVariant)
mobs.begin();
mobs.add(kind, seed, root, anim, flash?, tint?, tintMix?) // false — модели нет или переполнена: рисуй желейкой
mobs.end();                      // пустые сетки не рисуются; mobs.count — особей в кадре
mobs.clear(); mobs.dispose();
mobRoot(out, x, y, z, yaw, scale?, pitch?, roll?)  // корень из снимка: yaw сервера, модели смотрят по +Z
mobSeed(id)                      // постоянный seed 0…1 по номеру особи (у всех игроков одинаковый)
```

Одна часть одной модели — один `InstancedMesh` на `MOB_CAP = 72` особей; вспышка и оттенок — общие атрибуты особи на
все части модели. В кадре ничего не выделяется.

## Как вставить в орду

Готовая вставка — `client/fort/mobs/INTEGRATION.patch`: правит `client/fort/zombies3d.ts`, `client/fort/preview.ts`,
`test/fort-render.test.ts`. Снята с `rework/fort` `ec4301f`, проверена во временной копии вместе с наборами A, B, C, E:
`npm run check`, тесты крепости зелёные, превью — снимки `integ-*.jpg`.

1. Слить ветки мобов (`rework/mobs-a` и остальные) в крепость, затем `git apply client/fort/mobs/INTEGRATION.patch`.
   Если `zombies3d.ts` с тех пор поменялся и патч не лёг — те же шаги руками (ниже), патч — образец.
2. **Конструктор:** `new Zombies3D(scene, ground, models = ALL_MOBS)` → `this.mobs = new MobRenderer(scene, models)`
   (тени не отбрасывает: карта теней крепости статичная, иначе мобы впечатаются в неё призраками; пятна-тени остаются).
   `setQuality` → `this.mobs.setQuality(q, slow)`, `setFogGlow` → `this.mobs.setFogGlow(on)`, `clear` → `this.mobs.clear()`.
3. **Кадр:** `this.mobs.begin()` в начале `update()`, `this.mobs.end()` в конце. На каждую особь —
   `drawMob(...)`: если вернул `true`, **не рисовать** желейку: тело, лицо, руки, приметы вида (`extras`), бескозырку,
   щит, крылья, ядро босса. Тело, руки и пятно-тень больше не делят счётчик: у тела и рук свой (`jelly`), у тени — `n`.
   Если модели нет (или 72 места заняты) — желейка как раньше.
4. **Что остаётся общим (рисует крепость):** интерполяция `Track`, пятна-тени, полоски здоровья, метки и дорожки атак
   (`attackSignal`), пояс и корона ступени, камень Валуна над головой, цели прицела, мини-карта.
   Пояс и корона для модели ставятся в «оси хитбокса» вокруг неё: `_m = root × scale(sxz, def.height / BODY_H, sxz)`.
5. **Корень** (`drawMob`): `mobRoot(_root, r.x, r.y − rise·h·0,9, r.z, r.yaw, big, rise·0,5)`, где `h = hcy + hry`,
   `rise` — вылезание из земли (как у желейки), `big = 1,12` у чемпиона. Лазание, прыжок из лодки, пике — корень как есть
   из снимка, позу делает модель. **Босс в проёме ворот:** множители `gateSqueeze` считаются один раз (`gy` по высоте,
   `gxz` по ширине, с дрожью) и идут и в желейку, и в корень модели: `_root.multiply(makeScale(gxz, gy, gxz))` —
   неравномерный масштаб корня рендерер принимает, свет не ломается.
6. **Поза** (`animOf`, всё в `tr.anim`, без выделений):
   - `t` — секунды с появления на экране; `seed = mobSeed(id)` (вариант, рост, походка — у всех игроков одинаковые);
   - `gait += путь / MOB_STRIDE` (путь по земле и вверх-вниз по стене за кадр; телепорт > 1,5 м не считаем), `speed` —
     сглаженная скорость по земле (та же, что у желейки);
   - `st = r.st`; `stT` — секунды с начала состояния, а в `ZS_ATTACK` — с последнего удара (смена счётчика `atk` из
     снимка, как `atkT` у желейки): `min(time − stAt, atkT)`;
   - `hit` — `1` в `hit(id)` (событие `zhit`), гаснет за ~0,3 с; вспышка — `tr.flash × 0,85`;
   - `die` — 0 → 1 за `DIE_S = 1,1` с после `kill(id)` (у лодки — за `SINK_S`);
   - `rage = flags & ZF_RAGE`, `flags = r.flags`, **`stage = r.stage`** (у лодки — сколько экипажа ещё в ней).
7. **Оттенки** (`add(..., flash, tint, mix)`): босс открыт — `0x6ce5e3` 0,4; босс в ярости — `0xff4a3a` 0,22 + 0,14·sin;
   лекарь лечит — `0x9cff9a` 0,3 + 0,2·sin; экипаж в обычной модели — `0x5b9bd5` 0,25 (у особой модели экипажа — нет).
8. **Гибель:** сервер шлёт снимок раньше события `zdie`, поэтому в `push()` пропавший из снимка трек с моделью (и лодка)
   ждёт ещё один снимок — иначе `kill()` его уже не найдёт. Сбитый доигрывает гибель `DIE_S`: он уже не цель
   (`targets()` пропускает `dead`), без полоски, меток, пояса и короны, тень гаснет вместе с `die`.
   **Попутно чинится лодка:** раньше трек лодки удалялся до `kill()`, и потопленная лодка не тонула.
9. **Лодка:** `drawBoat` сначала пробует модель — `add(Z_BOAT, seed, mobRoot(x, y, z, yaw), anim)`: корень на воде,
   качку, вёсла, высадку и затопление делает модель (`anim.stage`, `anim.die`); полоска здоровья — как была. Корпус
   крепости — запасной (свой счётчик `hulls`).
10. **Экипаж (`ZF_CREW`):** модель выбирается по `anim.flags`: особые варианты с `when: ZF_CREW` (краб-абордажник у
    mobs-e). Пока у крабов `weight: 0` и выбор через `crewVariant()`, экипаж рисуется обычными шаркунами с синим
    оттенком. **mobs-e:** поставить крабам `when: ZF_CREW` (8) и вес 2 / 1 вместо `weight: 0` — тогда крепости ничего
    больше делать не нужно (в пробной копии так и сделано — снимок `integ-all-landing.jpg`).
11. **Превью** (`tools/fort-preview`): `?attack=lineup` — сразу парад, `?march=1` — парад идёт (походка),
    `?mobs=0` — все желейками (сравнить), `__fortPreview.kill(id)` / `hit(id)` — гибель и вздрагивание.
12. **Тест** `test/fort-render.test.ts`: `renderer(t, models = [])` — старые проверки на желейках (как были), новый тест —
    шаркун моделью, крылатка желейкой, Барон в воротах сжат (`gy < gxz`), `stage` дошёл до модели, гибель доигрывается и
    сбитый не цель.

Что решать агенту `fort` по ходу (зависит от моделей b–e): если модель Валуна держит свой камень — убрать `held` для
модели; щит щитоносца и бочку подрывника модели рисуют сами по `anim.flags`; корона висит над `def.height` и не
следует за наклоном головы — у моделей разная кость головы.

**Цена:** парад из 13 видов в превью — 122 вызова отрисовки против 51 у желеек (на «низком» — 103; сцена крепости
~40 из них). Обычная волна из 3–5 видов — +30…50 вызовов. Если станет тесно — следующий шаг: склеить части модели в
одну сетку (индекс кости + матрицы костей в текстуре) — 1 вызов на модель.
