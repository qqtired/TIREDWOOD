# Fortress v2 product laboratory implementation plan

> For agentic workers: execute this bounded laboratory natively with superpowers:executing-plans. No game implementation, Git or publication.

**Goal:** дать Роману управляемую осаду замка с различимыми исходами и прозрачным сравнением тактик.

**Architecture:** один автономный HTML, один three.js canvas с реальным CastleDecor и текущими мобами как явно подписанными эталонами. Чистая сценарная машина описывает фазы и выбор пользователя; отдельный расчёт использует актуальные функции оружия/башен/экономики. Новые GLB v2 подключаются после отдельного модельного ревью.

**Tech Stack:** Node24, локальные three.js/rolldown/Rubik из игры, HTML/CSS/JS. Новых зависимостей нет.

**Spec:** `./BRIEF-REV2.md`, принят ведущим для разработки лаборатории и расчётов.

## Global constraints

- V1 сохранён полностью в соседнем `v1/`; основной index не обновлять до визуального ревью.
- Только report/v2 и вспомогательные report assets; игровые исходники доступны только для чтения.
- Метеоры, снабжение, лихорадка, туман, паутина Ткачихи — существующее, не новые идеи.
- Один обязательный сценарий не чаще1на3волны; глобальные срочные очки2/3/4; запрещённые сочетания из брифа обязательны.
- Нет Chrome, Blender, сервера или полного build этим worker; ведущий даёт один согласованный Chrome проход.
- Расчёт и 3D-демо — не плейтест/вероятность победы.

## Review focus

- Ранний выбор и поздний выбор дают разные физические исходы, а не только текст.
- Перезапуск/смена сценария убирает старые тела/эффекты/таймеры и не дублирует ресурсы.
- Соло не получает одновременные поручения/закрытый единственный проход.
- AoE/ручной DPS/ремонт/смерть не смешиваются в один выдуманный урон, стоимость работы считается один раз.
- Эталонные старые clips, новые прототипы и настоящая игра подписаны отдельно; generic death запрещён для новых6.
