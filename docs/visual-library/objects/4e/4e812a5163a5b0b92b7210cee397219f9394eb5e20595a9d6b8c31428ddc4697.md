## Новые findings

### F1. Пауза/blur/offscreen отпускали заряд бильярда настоящим ударом — source исправлен, browser pending

Исходный путь: `source/stage.js:39,64` → искусственный `onKey('Space',false)` либо `ui.hold.up()` → `source/demos/modes/billiards.js:39,43,48` → `phase='rolling'`, `shots++`, velocity и звук удара.

Сценарий: начать бильярд, держать Space или кнопку силы, нажать Пауза / потерять фокус / прокрутить сцену за экран. Без физического отпускания игроком начислялся удар. Это blocker для обещанной pause/input acceptance.

Свежий source прочитан: `stage.js:13–15,39,47,64` вызывает `cancelInput` перед искусственными key-up/hold-up, натуральный pointerup/keyup остаётся действием. `billiards.js:48–49` нейтрально возвращает charge→aim и обнуляет силу до вызова release. Все 12 сцен получили cancellation hook, social/common очищает held keys. **Source-path закрыт.** В браузере проверить отдельно настоящий отпуск даёт ровно один удар, искусственная отмена — ноль; same pause для mouse hold, offscreen и blur.

### F2. «Настоящий дубль» джема выравнивал ранние/поздние ответы — source исправлен, browser/audio pending

Исходный `source/demos/social/reply-jam.js:28` записывал `offset`, но прежняя `:51` проигрывала ноты только в центре каждой доли. Раннее/позднее исполнение слышалось как идеальный ритм, хотя объявлялось настоящим дублем. Пропуски могли быть честно сохранены, но этого недостаточно для записи сыгранного ритма.

Сценарий: сыграть первый ответ в начале доли, второй ближе к её концу; послушать дубль. Ожидается сохранение разных относительных моментов, а не одинаковая середина.

Свежие `:28,46,51–59` независимо прочитаны: событие сохраняет `at=round*4+localT`, scheduler использует этот timestamp/offset, `note=-2` остаётся молчанием. Три ответных такта склеиваются в 12 с; это не запись всех countdown/call/between пауз полной сессии. **Source-path закрыт.** Проверить реальный звук и strum/hit на раннем/позднем событии в browser, а не только число capture entries.

### F3. Торт при ошибке не падает с подноса — OPEN, blocker видимого failure

`source/demos/social/picnic-carry.js:54`: при `abs(slide)>.79` торт только поворачивается на ±1,3 rad и фаза становится failure. `:59–62` **на каждом последующем update вновь ставят cake на cake_seat** и добавляют тот же slide. В failure нет вертикальной скорости/гравитации/отдельного world transform. Рука продолжает держать поднос, а торт остаётся его дочерним объектом на высоте сиденья.

Сценарий: начать default balance и довести соскальзывание до края. Пользователь получает «Торт стал десертом…», но самостоятельной траектории падения нет. PRODUCT-BRIEF:120 и handoff строка picnic обещают реальное падение и видимую причину/траекторию.

Ожидается отделить торт в world space при срыве, сохранить начальную позицию/наклон/скорость, дать падение до настила и вернуть на seat при retry. Нельзя заменить это счётчиком или единственным поворотом. Root назначает отдельного writer; исправление в этом review ещё не прочитано.

### F4. Адаптеры Boat/Kart теряют штатные update/dispose акторов — OPEN, blocker анимации рук и ownership

`source/kit.js:57–74` создаёт реальные классы, один раз обновляет Avatar, переподвешивает `rider.root` под `vehicle.root` и возвращает лишь Object3D. Ссылки на class instance/update/dispose теряются для callers. `source/demos/modes/common.js:192–195` дальше изменяет только transform root; steering wheel, миттенки и native actor state не обновляются за вводом.

Другая сторона дефекта: vehicle Avatar не находится в `Diorama.jellies`; `game-opus/client/lab/kit3d.ts:501–504` не вызывает его Avatar.dispose, и общий `disposeTree:267–277` проходит по его shared meshes/materials. Это нарушает прямой контракт disposer «общие ресурсы желеек не трогаем — снимаются раньше». Production предусмотрел собственные BoatModel.dispose (`regattaboat.ts:387–400`) / Kart3D.dispose (`kart3d.ts:444–453`) и Avatar.dispose (`avatar.ts:1010–1033`). Не выдаю это за уже измеренную утечку GPU; отсутствие штатного ownership и обновлений подтверждено по source.

Сценарии: газ/A/D — карт/катер движется, но руки/руль остаются исходной позой; затем regatta→kart→social→model cycles вызывают общий disposer на production shared actor geometry.

Ожидается facade с сохранённым class instance, native update с переводом локального состояния в native pose и tracked dispose до общего Diorama.dispose. **Нельзя просто вызвать native update с текущим nested Avatar:** native pose world-space, поэтому возникнет двойной transform. Нормальная production схема — vehicle.root и Avatar.root/shadow отдельно в active scene. Координатору передано точное guidance; root назначил исправление. После него нужен source re-read, затем root mouse input / руки / циклы удаления в browser.

### F5. Бриф обещает три принятых задачи бильярда, source содержит один срез — OPEN, blocker согласованного объёма

`PRODUCT-BRIEF.md:108`: в первой lab принимается одна расстановка **из каждого** типа Точность / Борт / Позиция. `source/demos/modes/billiards.js:31,41,58–60,70` — одна неизменная расстановка двух шаров, одна угловая луза, без выбора задачи, проверки «борт до контакта» или конечной позиции битка. `data/modes.mjs:7` честно называет это «Один учебный срез», то есть внутренние источники противоречат друг другу. `source/depth.mjs:16` также называет три типа первым пакетом.

Сценарий: пользователь ищет принятые Борт/Позиция и их вариант/повтор — доступны только тот же cut и необязательная подсказка. Ожидается закрыть принятый объём тремя реальными judges/раскладками и контролом выбора; косметическое переименование исходной одной задачи не решает finding. Root уже назначил modes writer; его свежий результат ещё не прочитан.

### F6. Пауза во время async factory теряется после её завершения — OPEN, blocker lifecycle-паузы

`source/stage.js:49` ожидает async factory, а `:52` безусловно делает `this.paused=false`, начинает loop и заменяет статус. `source/main.js:58` позволяет нажать Пауза во время ожидания и меняет кнопку на «Продолжить».

Сценарий: выбрать новую сцену, пока pending GLB/Boat.ready нажать Пауза; factory завершается. Сцена сама начинает обновляться/принимать ввод, а кнопка может продолжать говорить «Продолжить». Точное окно зависит от фактического async load; этот race подтверждён структурой исходника, browser reproduction пока не получена.

Ожидается сохранять pause intent на весь current generation либо явно заблокировать pause во время loading с понятной надписью. Root notified. Browser check pending→pause→ready, потом осознанный resume и проверка button/status/state согласованности.

## Что соответствует требованиям по исходникам

- 6 режимов + 6 социальных контроллеров — разные механики, не 12 копий декоративного вращения. Направление/тайминг/выстрел/placement меняют вычисляемые исходы; failure/retry пути существуют. Это наличие source-пути, не доказательство достижимого успеха в браузере.
- Chalk (`chalk-relay.js:36–49`) копирует реальные позиции/время завершённого авторского прохода; до proof ghost не активен. Kart (`kart.js:42–59`) сохраняет запись только на завершённом чистом круге и использует её на повторе. Это существенно лучше v1; нельзя принимать только ghostFrames>0 без просмотра движения.
- Пейнтбол использует настоящий Avatar gun/muzzle/onShot (`paintball.js:27–40`), actual ray/cover/foe/hp пути и escort guard (`:54–73`), исключающий автопобеду от ожидания у старта. Полный AI/живые команды честно не заявлены.
- Social objects/Avatar/worldGrip source подключены: контакты считаются после Avatar update. `maxGripError` измеряет принудительно поставленные mesh origins, а не визуальный контакт всей варежки/физическую досягаемость. В browser нужны реальные руки/поверхности и `heldContact.sources` с авторскими GLB anchors; один маленький error не является визуальной приёмкой.
- Async generation stop/cleanup (`stage.js:47–53`) изолирует панели: stale factory disposal удаляет собственный localPanel; source не стирает новую controls панель. Один renderer/RAF объявлен централизованно; demos не создают свои window handlers или RAF.
- Model view имеет scoped title/goal/return, а `.model-view` в style.css скрывает content-strip/depth/evidence/add-feature от предыдущей фичи. Здесь прежний finding о чужом контенте source закрыт.
- Iteration 1 действительно меняет объём/список, iteration 2 перечисляет конкретную критику и дельты, iteration 3 содержит реальные исправления и открытые пункты. Третью нельзя объявлять завершённой до фактической final bundle + browser QA.
- Build source отдельно маркирует ImageGen и Blender, заново конвертирует текущий render PNG, не подставляет посторонний Blender-набор картингу/пейнтболу/бильярду; baseline SHA перечитываются. Это правильная форма provenance, но её фактический final receipt ещё требуется.
