# «Волна» 3 — игровая интеграция

Владелец принял концепцию и размер нового аквапарка в обзоре
`tiredwood-product-lab-v2-2026-10-12`. Условие: сохранить любимые механики,
улучшить фактуры и связь с берегом; полукруглая компоновка допустима.

При `PLAZA3=1` полоса имеет номер **3**. Без флага остаются прежние геометрия,
оформление и номер **2**. Код курса — `shared/aqua.ts`; движение и попадания —
`shared/aquadyn.ts`. Игрок проходит обычными клавишами, прыжком и рывком.
Падение возвращает на старт и снимает попытку. Промежуточных сохранений нет.

Маршрут: подушки → паром → четыре тонущие опоры → два батута → башня и горка →
вертушка → бревно с тремя мешками → лифт → вторая вертушка → тумба →
встречные паромы → финиш. Первая ветвь плавно отходит к северу, западная
обходит бухту, обратная возвращается к берегу. Силы батутов, время перевозов,
предупреждение о погружении, толчки, таймер и восстановление сохранены.

Игровые опоры занимают x −94.6…−33.8, z 5.1…42. Буйковая линия снаружи,
деревянные рамы доходят до z43.65. Рыбацкие причалы, лодки и восточная регата
не пересекаются. У невидимой границы меняются только связанные сегменты
`wall.farWest`, `wall.southWest`, `wall.bayWest`: западная перемычка проходит
на z44…45. Источник — `docs/plaza3/level/layout.json`, затем генератор
`tools/plaza3/layout.mjs`. Старую карту этот перенос не затрагивает.

Настоящие модули Blender v3 и происхождение — `client/assets/aqua/v3/`.
`client/lobby/aquamodels.ts` читает отдельные узлы, приводит размеры к
игровой геометрии и воде. `client/lobby/aquapark.ts` склеивает неподвижные
части, а подвижные ставит по тем же функциям, что сервер. У горки сохранена
игровая линия ската, у мешков — длина подвеса, у вертушек — длина трубы.
ПВХ мягко матовый, швы геометрические; дерево имеет отдельную фактуру.
`AquaPark.ready` и `models.ready/error` показывают результат загрузки.

Проверки: `PLAZA3=1 node --test test/aqua.test.ts test/aqua-model.test.ts`
и тот же запуск с `PLAZA3=0`. Робот проходит весь маршрут через сервер,
сверяет клиентское предсказание на каждом вводе и повторяет прохождение
при неровной доставке. Отдельно проверяются реальные механизмы, восстановление,
финиш, рекорды, непересечение границ и GLB-геометрия.

Запись рекордов прошлой версии в архив выполняется общим блоком миграции
профилей. В рабочей копии одного аквапарка эта миграция не реализована:
до её интеграции запуск на сохранениях игроков запрещён. Общий build,
браузерная приёмка и бюджет кадра проверяются ведущим в общей сборке.
