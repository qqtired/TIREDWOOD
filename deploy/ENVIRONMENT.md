# Переменные Game Opus

После прямого разрешения владельца опубликован релиз **20261003-090248**. Все девять флагов ниже установлены в1 и проверены в действующей службе; VOICE экспериментальный. Nginx, TURN и сетевые порты не менялись. [Backup, миграция и production-проверки](../docs/release-prep/2026-10-03/REPORT-release.md). Следующие изменения production требуют соответствующего разрешения; примеры ниже сами ничего не применяют.

## Флаги режимов

Значения — строки `1` или `0`. Иные непустые значения не включают режим. DEV означает запуск с `--dev` (`npm run dev`), а не только переменную `NODE_ENV`.

| Переменная | Возможность | Если не задана в DEV | Если не задана в собранном запуске |
|---|---|---|---|
| `FORTRESS` | Крепость | включена | выключена |
| `FIGHT` | Fight Club | включён | выключен |
| `SKILL` | Полоса «Выше облаков» | включена | выключена |
| `BOATRACE` | Гонки на катерах | включены | выключены |
| `HIDE` | Прятки предметами | включены | выключены |
| `STORM` | Общий шторм | включён | выключен |
| `PIRATES` | Пиратский налёт | включён | выключен |
| `VOICE` | Голос по удержанию V, до 6 участников комнаты | включён | выключен |
| `FISH2` | Рыбалка 2.0, 32 вида | выключена | выключена |

Для флагов кроме `FISH2` значение `1` принудительно включает, `0` выключает и в DEV. Для `FISH2` требуется явное `1`; отсутствие/`0` сохраняют старую рыбалку. Флаги передаются серверу; отдельной клиентской настройкой включить скрытый режим нельзя.

Blackjack, добровольные карточные ставки, общий уровень и его проверенная миграция отдельного флага не имеют. Общий XP и рыбацкий XP независимы. Голос передаётся по WebRTC; игровой WebSocket обслуживает только согласование. Параметры ICE и отключение описаны в [voice-mvp.md](../docs/voice-mvp.md). Это не установка TURN и не изменение действующей службы.

## Безопасные локальные примеры

Node 24+. Команды ниже — примеры для ручного локального запуска; документация их не выполняет. Временный `DATA_DIR` отделяет проверки от существующих профилей.

Все новые режимы и рыбалка 2.0 в разработке:

```bash
DATA_DIR=$(mktemp -d) \
FORTRESS=1 FIGHT=1 SKILL=1 BOATRACE=1 HIDE=1 STORM=1 PIRATES=1 FISH2=1 \
npm run dev
```

Та же конфигурация для локальной проверки собранной версии, без DEV:

```bash
DATA_DIR=$(mktemp -d) \
FORTRESS=1 FIGHT=1 SKILL=1 BOATRACE=1 HIDE=1 STORM=1 PIRATES=1 FISH2=1 \
npm run play
```

Один воспроизводимый шторм в DEV; `DEV_PIRATES=now` аналогично используют отдельным сценарием с `PIRATES=1`:

```bash
DATA_DIR=$(mktemp -d) \
STORM=1 PIRATES=0 DEV_STORM=now DEV_WEATHER=clear \
FORTRESS=0 FIGHT=0 SKILL=0 BOATRACE=0 HIDE=0 FISH2=1 \
npm run dev
```

`DEV_STORM=now`, `DEV_PIRATES=now`, `DEV_WEATHER` и `DEV_RIG` не являются production-переключателями. Шторм/пираты координируются одним серверным планировщиком: не перекрывают друг друга и обычный дождь; активное большое событие блокирует покупку дождя бубном до списания жетонов.

Игра читает `process.env`; эти строки не означают автоматическую загрузку `.env`. Действующий способ передачи переменных — оболочка или systemd unit после согласования. `HOST`, `PORT`, `DATA_DIR` и остальные общие параметры описаны в [README](../README.md#как-запустить).

## Пример для обсуждения production-конфигурации

Ниже только **пример выключенных новых флагов**, не файл для установки и не полный unit:

```ini
Environment=SKILL=0
Environment=BOATRACE=0
Environment=HIDE=0
Environment=STORM=0
Environment=PIRATES=0
```

Существующие `FORTRESS`, `FIGHT`, `FISH2`, пути данных и прочие настройки нужно сверить отдельно; этот фрагмент их не заменяет. Включение выбранного нового режима означает явное изменение соответствующего значения на `1` в согласованном релизе. Само наличие примера не разрешает менять службу или запускать installer.

## Данные перед первым запуском новой версии

Миграция `fishingResetVersion=1` при чтении старого профиля обнуляет только `fishing.xp`, `questsDone`, `questCaught`, `rod`. Удочки зарабатываются заново — это подтверждённое требование. Альбом/виды/уловы/веса/максимумы/забросы/поклёвки/срывы/рейтинги, жетоны, вещи и `beerUntil` сохраняются. Новый профиль сразу помечен текущей версией; повторный вход/загрузка с маркером не сбрасывает заработанное. `levelsVersion=1` отдельно сохраняет однократный исторический пересчёт общего XP из статистики.

Платные Blackjack и Durak имеют отдельные резервы в профиле. Новый процесс возвращает незавершённые резервы однократно без XP; штатное завершение сервера сначала закрывает карточные расчёты. Бесплатный Blackjack со ставкой 0 резервов не создаёт. Durak разыгрывает только банк согласившихся участников, а возврат собственной ставки опыта не даёт.

До разрешённого выпуска нужны: снимок данных **после штатной остановки**, сохранённые совместимые код/unit, проверка нормализации на копии и сравнение сохраняемых полей. После согласованного запуска — повторная сверка. Старый код может отбросить новые поля при сохранении, поэтому простой откат symlink не является безопасным откатом данных. Локальные тесты синтетических профилей не заменяют эту проверку.

Проверки кандидата: `npm run check`, `npm test`, `npm run build`, затем согласованная desktop-приёмка и короткая мобильная проверка. Обязателен существующий CSP-сценарий собранной версии. Результаты общего gate/браузера фиксирует ведущий отдельно; здесь статуса PASS для выпуска нет. `/health.busy` и fail-closed guard существующего deploy не следует обходить автоматически через `FORCE=1`.
