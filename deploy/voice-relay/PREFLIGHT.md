## Версию нельзя выбирать через слепой apt install

Доступный пакет старый. Upstream описывает обход loopback-защиты до 4.12.0 включительно и исправление в 4.13.0; отдельный дефект сравнения IPv6-диапазонов затрагивает версии до 4.15.0 и исправлен в 4.16.0. Явные ACL/IPv4-only уменьшают применимость отдельных сценариев, но не заменяют проверку патчей пакета. Наличие исправлений в Ubuntu-пакете `4.6.1-1build4` здесь **не подтверждено**. [Loopback advisory](https://github.com/coturn/coturn/security/advisories/GHSA-w4hf-cr3w-6h79), [IPv6 range advisory](https://github.com/coturn/coturn/security/advisories/GHSA-4v97-rxjj-4f99).

Предлагаемый артефакт — официальный coturn **4.18.0**, commit **23c6c1d32a3d2b21a56cee65d3203bcc4ea82d2b**; соответствие тегу проверено через `git ls-remote`. Та же версия уже работала в локальном тесте macOS. Для VPS нужна отдельная Linux-сборка: версия исходников не доказывает работоспособность Linux-бинарника. [Release](https://github.com/coturn/coturn/releases/tag/4.18.0).

До публикации: собрать этот commit в совместимой Ubuntu 24.04 среде, сохранить hash артефакта, проверить связанные библиотеки, startup под подготовленным unit и отрицательные проверки аутентификации/ACL. Зависимости сборки по upstream: C toolchain, OpenSSL 3+, libevent2, libmicrohttpd; опциональные SQL/Redis backends не нужны для `static-auth-secret`. Установочный префикс `/opt/game-opus-turn/4.18.0`. Сборку/зависимости на production не устанавливали. Точный Linux-бинарник и его проверка пока остаются незавершённой подготовкой, а не скрытой гарантией. [Build instructions](https://github.com/coturn/coturn/blob/4.18.0/docs/Build.md).

## Ёмкость: шесть участников — ограничение комнаты

`server/voice.ts` ограничивает участников по объекту комнаты; общего лимита комнат/relay allocations в игре нет. `server/hub.ts` создаёт до восьми комнат: lobby, paintball, race, skill, boatrace, hide, fort, fight. Каждая может иметь шесть голосовых участников. Один человек создаёт пять peer connections, полная комната — 30 конечных соединений (15 пар × 2 стороны).

Плановая формула headroom: `30 × 2 транспорта TURN × 2 поколения ICE × число полных комнат`. Это резерв, не измеренная гарантия: дополнительные интерфейсы браузера, запоздалое освобождение allocations и reconnect storms требуют проверки.

| Объём | `total-quota` | UDP relay range | `bps-capacity`, bytes/s на направление |
|---|---:|---|---:|
| Один полный шестичеловечный пилот | 120 | 49160–49287, 128 портов | 1 920 000 |
| Две полные комнаты | 240 | 49160–49415, 256 портов | 3 840 000 |
| Все восемь комнат | 960 | 49160–50183, 1024 порта | 15 360 000 |

В файле `turnserver.conf.example` оставлен **пилотный** бюджет: 120 allocations / 128 портов. Это общий пул для всех комнат, не изоляция одной комнаты: при превышении он откажет новым allocations. Выпускать этот бюджет под обещание одновременной работы всего мира нельзя. Полный вариант отличается ровно `max-port=50183`, `total-quota=960`, `bps-capacity=15360000` и соответствующим диапазоном сетевых правил; `user-quota=20`, `max-bps=16000` сохраняются. Значение 15.36 MB/s — верхний лимит (~122.88 Mbit/s в направлении), не ожидаемый расход. Тариф/лимит трафика провайдера не проверен. CPU/RAM caps unit не масштабировать вслепую: сначала нагрузка.

## Что именно требует нового разрешения

Согласуемое действие: установить проверенный pinned Linux-артефакт, создать отдельного пользователя/службу `game-opus-turn`, свежий HMAC-секрет в приватных файлах, открыть/разрешить **UDP и TCP 3478 плюс выбранный UDP relay range** и подключить игровые `VOICE_TURN_URLS`/`VOICE_TURN_SECRET` через отдельный systemd drop-in. Базовый вариант — без DNS, Nginx, TLS-ключей и TCP 443/5349. На хосте нет блокирующего firewall: запуск listener сам создаёт новую публичную доступность, даже если правила добавлять не потребуется. Provider ACL проверяется до старта.

Для текущего устройства игры предпочтителен **полный восьмикомнатный бюджет**, с отдельной нагрузочной приёмкой. Если согласован только 128-портовый пилот, результат явно остаётся пилотом с общей квотой; игрового admission control для ограничения одной комнатой нет.

После разрешения порядок конкретный:

1. Подготовить/проверить Linux-бинарник и окончательный config под согласованный бюджет; исключить test-only loopback exceptions. Проверить unit через `systemd-analyze verify`, локальные UDP/TCP allocations, bad/expired auth, запрет защищённых адресов на контролируемом тестовом listener. Не сканировать внутренние сервисы/metadata.
2. Сохранить прежние игровые unit/drop-ins приватно; для изменения игры использовать штатный release backup/data gate. Сгенерировать секрет непосредственно в config и env-файл без печати. Доступ: config root:game-opus-turn 0640, env root:root 0600.
3. Проверьте provider ACL и правило/диапазон публикации. Установить только новую службу, не менять общую firewall policy, SSH/HTTP/HTTPS или другие сервисы. Запустить relay, проверить фактические listeners и отказ unauthenticated allocation.
4. Добавить EnvironmentFile-drop-in игры, не заменяя её unit и остальные флаги. В штатном согласованном рестарте подключить UDP/TCP TURN URLs; normal mode `VOICE_RELAY_ONLY=0`.
5. Две внешние сети: отдельно UDP-only и TCP-only forced relay, двусторонний Opus и PTT release; затем обычный ICE. Далее шесть участников одной комнаты, переходы/переподключения; восьмикомнатную ёмкость принимать только по отдельному нагрузочному результату. TLS-only корпоративные сети остаются за границей этого baseline.
6. Если gate не проходит: восстановить прежний игровой voice drop-in/env, штатно перезапустить игру, остановить relay. Удалять только новые правила с подтверждённым владением; не откатывать профили/прогрессию ради голосового транспорта.
