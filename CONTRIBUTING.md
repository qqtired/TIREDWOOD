# Как помогать с TIREDWOOD

Сначала запустите игру у себя — [README → Быстрый старт](README.md#быстрый-старт). Если набережная открылась, всё готово.
Что сейчас на сайте и что планируется дальше — [README → Состояние](README.md#состояние) и [docs/STATUS.md](docs/STATUS.md).

## Доступ

Репозиторий публичный: читать, скачивать и запускать может кто угодно.

Пушить в него могут те, кого пригласил владелец. Пришлите ему свой ник на GitHub, потом примите приглашение
из письма или на странице https://github.com/qqtired/TIREDWOOD/invitations.

Без приглашения тоже можно предложить правку: нажмите **Fork** на GitHub, работайте в своей копии и откройте
Pull Request оттуда.

## Как вносить изменения

В `main` напрямую не пушим. Каждая задача — своя ветка и Pull Request:

```bash
git switch main
git pull
git switch -c vasya/udochka-2
```

Имя ветки — ваш ник и коротко, что делаете. Дальше:

1. Правите код, коммитите с понятным описанием: `git commit -m "Рыбалка: вторая удочка в лавке"`.
2. Перед отправкой прогоните проверки — все три должны пройти:
   ```bash
   npm run check
   npm test
   npm run build
   ```
3. Коротко сыграйте в браузере на `npm run dev` в то, что поменяли. Рыбалка 2.0 в разработке включается только явно:
   `FISH2=1 npm run dev`.
4. Отправьте ветку: `git push -u origin vasya/udochka-2`. Git напечатает ссылку — откройте её и нажмите
   **Create pull request**. В описании: что сделано, как посмотреть, что не проверено.
5. Владелец смотрит и вливает в `main`. Пока ждёте — можно браться за следующую задачу в новой ветке.

Если `main` ушёл вперёд и GitHub пишет про конфликт:

```bash
git switch vasya/udochka-2
git pull origin main
```

Поправьте файлы, которые git отметил конфликтом, закоммитьте и снова `git push`.

Вливание в `main` ещё не выкладка: на game.tired.solutions новое попадает, только когда владелец выпустит
релиз.

## Правила проекта

Подробно — в [AGENTS.md](AGENTS.md), [ASTRA.md](ASTRA.md) и [docs/design.md](docs/design.md). Коротко:

- **Десктоп — главная платформа.** Клавиатура, мышь, обычный браузер. Телефон не ломаем, но и не задерживаем
  ради него десктоп.
- **Новое — за флагом сервера.** Пример — `FIGHT` или `HIDE` в `server/main.ts`: без переменной режим включён только
  в `npm run dev`. Без флага игра должна вести себя ровно как раньше. Какие флаги включены на сайте, видно
  в `deploy/game-opus.service`.
- **Своё — в новых файлах.** В общих файлах (`client/app.ts`, `server/hub.ts`, `shared/messages.ts`,
  `shared/maps/lobby.ts` и т. п.) — только короткие точечные подключения. Похожий готовый режим — лучший
  образец: Fight Club (`shared/fight*.ts`, `server/fight/`, `client/fight/`), прятки (`shared/hide*.ts`, `server/hide/`,
  `client/hide/`) или картинг.
- **Решает сервер.** Жетоны, победы и рекорды считает сервер, клиенту не верим. Награды — в
  `shared/economy.ts` или рядом с режимом.
- **Протокол.** Поменяли формат сообщений — поднимите `PROTOCOL_VERSION` в `shared/constants.ts`. Если в `main` номер
  уже больше, чем на сайте (см. «Состояние» в README), второй раз поднимать не нужно.
- **Тесты.** Новая логика — тест в `test/<тема>.test.ts`.
- **Не лагать.** Повторяющееся рисуйте инстансами, без тяжёлых пост-эффектов.
- **Памятник не трогаем:** `statue*.ts`, `client/assets/statue`, `tools/statue`, `test/statue.test.ts`.
- **Прогресс игроков.** Меняете схему профилей — старые сохранения должны загружаться без потерь
  (см. «Сохранность прогресса» в AGENTS.md).

## Чего не коммитить

`data/` (локальные профили и токен проверки), `.env`, токены, пароли, ключи, `node_modules/`, `dist/` —
большая часть уже в `.gitignore`. Картинки и модели — только свои, сгенерированные или под свободной
лицензией; источник и лицензию записывайте рядом, как в `client/assets/critters/`.

Случайно закоммитили секрет — сразу скажите владельцу. Удалить коммит мало: токен нужно поменять.
