# TIREDWOOD — правила для помощников

Игра называется **TIREDWOOD** (раньше Game Opus). Папка, пакет и служба на сервере по-прежнему называются `game-opus` —
не переименовывай их. **Обязательно прочитай [ASTRA.md](ASTRA.md):** там порядок работы и все запреты (выкладка только
после «да» владельца, секреты, `chatgame/`, памятник, вход на боевой сайт, ник «Проверка», временный `DATA_DIR`, python3).
Они действуют и для Codex, и для любого другого помощника.

Коротко о проекте:

- Что на сайте, что лежит в коде и ещё не выложено, — раздел «Состояние» в [README.md](README.md); план дальше —
  [docs/STATUS.md](docs/STATUS.md).
- Флаги режимов — в `server/main.ts`, на сайте — строки `Environment=…=1` в `deploy/game-opus.service`. Сейчас включены
  `FORTRESS`, `FIGHT`, `FISH2`, `SKILL`, `BOATRACE`, `HIDE`, `STORM`, `PIRATES`, `VOICE`, `GIFTS`, `LAB`, `JUKEBOX`, `ROULETTE`.
- Образцы для нового режима: Fight Club (`shared/fight*.ts`, `server/fight/`, `client/fight/`), прятки (`shared/hide*.ts`,
  `server/hide/`, `client/hide/`), картинг (`server/race/`, `client/race/`).
- Проверки после каждой задачи: `npm run check && npm test && npm run build`.

## Десктоп — основная платформа

- Проектировать и доводить игру прежде всего для компьютера: клавиатура, мышь и обычный настольный браузер.
- Главные критерии приёмки: удобство управления, читаемость боя и интерфейса, стабильный FPS и полноценные игровые сценарии на десктопе.
- Основное время разработки, визуальной проверки и оптимизации направлять на десктопную версию. Сначала завершать запрошенные игровые механики и их проверку на компьютере.
- Мобильную совместимость сохранять и выполнять короткую проверку базовой работоспособности. Исправлять критические поломки, но не задерживать десктопные функции ради отдельной мобильной полировки, многочисленных размеров экрана или детальной настройки сенсорного управления.
- Углублённую мобильную проработку выполнять, когда Роман отдельно её запросит или когда обнаруженная проблема затрагивает также основную десктопную игру.
- В отчёте отдельно указывать результат десктопной приёмки и объём мобильной проверки; не выдавать эмуляцию телефона за проверку на реальном устройстве.

Эти правила задают приоритет проверки и не разрешают ломать уже работающие мобильные сценарии.

## Сохранность прогресса при релизе

- Перед изменением схемы профилей сохранять согласованный снимок данных после штатного завершения сервера, предыдущую сборку и unit; проверять целостность копий.
- До запуска новой версии проверять её нормализацию на текущем серверном сохранении без записи в рабочие данные. Альбомы, рекорды, счётчики и полученные вещи должны сохраняться. После запуска сверять сохранность повторно, учитывая новый улов игроков.
- Откат одного кода не считать безопасным: старый Store отбрасывает неизвестные поля прогресса, новые виды рыб и новые подарочные вещи. Подбирать совместимые код и данные, сохранять вытесняемое состояние и не обнулять достижения игроков.
